# Routing Policies & Strategies

Comprehensive guide to intelligent request routing in Igris Inertial, including Thompson Sampling, speculative execution, and semantic routing.

## Overview

Igris Inertial provides **multiple routing strategies** to optimize LLM inference across providers:

- **Thompson Sampling** - Bayesian multi-armed bandit with adaptive learning
- **Speculative Execution** - Race multiple providers for 60% faster TTFT
- **Semantic Routing** - ONNX-powered ML classification for intent-based routing
- **Cost-Aware Routing** - Automatic selection based on cost optimization
- **Council Mode** - Multi-provider consensus for +15-20% quality improvement
- **Round Robin** - Simple load distribution
- **Least Latency** - Select fastest provider
- **Least Load** - Select provider with lowest current load

## Routing Strategies

### 1. Thompson Sampling (Recommended)

**Bayesian multi-armed bandit** algorithm that balances exploration and exploitation.

```go
router := router.NewAdaptiveRouter(
    router.PolicyThompsonSampling,
    5*time.Minute, // Metrics window
)
```

**How it works:**
1. Each provider maintains **α (successes)** and **β (failures)** parameters
2. For each request, sample from **Beta(α, β)** distribution
3. Select provider with **highest sample** (exploitation) or **random** (exploration)
4. Update α/β based on **outcome** (latency, cost, errors)

**Configuration:**
```go
type ThompsonSamplingConfig struct {
    ExplorationRate  float64  // Default: 0.15 (15% exploration)
    SuccessThreshold float64  // Default: 0.6
    InitialAlpha     float64  // Default: 1.0
    InitialBeta      float64  // Default: 1.0
}
```

**Reward Calculation:**
```
reward = (0.4 × latency_score) + (0.3 × cost_score) + (0.3 × success_score)

where:
  latency_score = 1 - (latency / max_latency)
  cost_score = 1 - (cost / max_cost)
  success_score = 1 if no error, 0 otherwise
```

**Example:**
```bash
curl -X POST http://localhost:8080/v1/infer \
  -H "Content-Type: application/json" \
  -d '{
    "model": "gpt-4",
    "messages": [{"role": "user", "content": "Explain Thompson Sampling"}],
    "routing_policy": "thompson-sampling"
  }'
```

**Response Metadata:**
```json
{
  "metadata": {
    "provider": "openai/gpt-4",
    "routing_decision": "thompson-sampling",
    "thompson_sampling_score": 0.87,
    "exploration": false,
    "alternatives": ["anthropic/claude-3-sonnet"]
  }
}
```

### 2. Speculative Execution (Growth+ Tier)

**Race multiple providers** in parallel and deliver tokens from the fastest responder.

```bash
curl -X POST http://localhost:8080/v1/infer \
  -H "Content-Type: application/json" \
  -d '{
    "model": "gpt-4",
    "messages": [{"role": "user", "content": "Hello!"}],
    "stream": true,
    "speculative_mode": "latency"
  }'
```

**Speculative Modes:**

| Mode | Latency Weight | Quality Weight | Cost Weight | Use Case |
|------|---------------|----------------|-------------|----------|
| **latency** | 0.7 | 0.2 | 0.1 | Real-time chat, interactive |
| **balanced** | 0.4 | 0.4 | 0.2 | General purpose |
| **quality** | 0.2 | 0.6 | 0.2 | Content generation |
| **cost** | 0.2 | 0.2 | 0.6 | Batch processing |

**Configuration:**
```bash
# Enable speculative execution (disabled by default)
ENABLE_SPECULATIVE=true
MAX_SPECULATIVE_PROVIDERS=3      # Race 3 providers
FIRST_TOKEN_TIMEOUT=5s           # Timeout for first token
EARLY_TOKEN_COUNT=5              # Fallback buffer size
WASTE_THRESHOLD=0.30             # Auto-disable at 30% waste
```

**Performance Gains (from v1.2.1):**
- **60% faster p50 TTFT**: 450ms → 180ms
- **62% faster p95 TTFT**: 850ms → 320ms
- **96% fewer stream failures**: 2.5% → 0.1%
- **20% lower cost**: $0.015 → $0.012 per request

**Mid-Stream Switching:**
```
┌──────────────────────────────────────────────────────┐
│ Race Phase (0-5s)                                    │
│                                                      │
│  Provider A: ████░░░░░░░░ (240ms TTFT)             │
│  Provider B: ███████░░░░░ (180ms TTFT) ← Winner     │
│  Provider C: ██░░░░░░░░░░ (350ms TTFT)             │
└──────────────────────────────────────────────────────┘

┌──────────────────────────────────────────────────────┐
│ Streaming Phase (Winner: Provider B)                │
│                                                      │
│  Tokens: Hello, I can help...                       │
│  Buffer: [5 tokens stored for fallback]             │
│                                                      │
│  Provider B fails at token 50                     │
│  Switch to Provider A (buffered tokens)          │
└──────────────────────────────────────────────────────┘
```

**Cost Accounting:**
```go
// Per-tenant cost tracking
type CostStats struct {
    TotalWinnerCost  float64  // Cost of winning providers
    TotalWastedCost  float64  // Cost of losing providers
    WasteRatio       float64  // wasted / (winner + wasted)
    RequestCount     int
    AutoDisabled     bool     // True if waste > threshold
}
```

**Auto-Disable on Waste:**
```
If waste_ratio > 30% for a tenant:
  1. Auto-disable speculative mode for 5 minutes
  2. Log warning message
  3. Send alert to monitoring
  4. Resume after cool-down period
```

### 3. Council Mode (Growth+ Tier)

**Multi-provider consensus** for improved response quality.

```bash
curl -X POST http://localhost:8080/v1/infer \
  -H "Content-Type: application/json" \
  -d '{
    "model": "gpt-4",
    "messages": [{"role": "user", "content": "Complex reasoning task"}],
    "council_mode": true,
    "council_providers": ["openai/gpt-4", "anthropic/claude-3-opus"],
    "consensus_threshold": 0.7
  }'
```

**How it works:**
1. Send request to **multiple providers** in parallel
2. Collect **all responses**
3. Use **LLM judge** to evaluate quality and consistency
4. Return **highest quality response** or **synthesized answer**

**Quality Improvements (measured):**
- **+15-20% quality** on reasoning tasks
- **+12% accuracy** on factual questions
- **Better hallucination detection** via cross-validation

**Configuration:**
```go
type CouncilConfig struct {
    MinProviders       int      // Default: 2
    MaxProviders       int      // Default: 3
    ConsensusThreshold float64  // Default: 0.7
    JudgeModel         string   // Default: "gpt-4"
    Timeout            time.Duration
}
```

### 4. Semantic Routing

**ONNX-powered ML classification** for intent-based routing.

```bash
curl -X POST http://localhost:8080/v1/infer \
  -H "Content-Type: application/json" \
  -d '{
    "model": "auto",
    "messages": [{"role": "user", "content": "Write creative story"}],
    "enable_semantic_routing": true
  }'
```

**Classification Categories:**
- **Creative**: Stories, poetry → Route to Claude (better creativity)
- **Analytical**: Data analysis, math → Route to GPT-4 (better reasoning)
- **Coding**: Code generation → Route to DeepSeek Coder
- **Conversational**: Chat, Q&A → Route to GPT-3.5 (cost-effective)
- **Translation**: Language translation → Route to specialized models

**Model Architecture:**
```
Input Text → HuggingFace Tokenizer → ONNX Classifier → Category + Confidence
                                                              ↓
                                                    Provider Selection
```

**Configuration:**
```yaml

enable_semantic_routing: true
classification_confidence_threshold: 0.6
classification_cache_ttl_seconds: 3600

# Routing rules
semantic_routing_rules:

    providers: ["anthropic/claude-3-sonnet", "anthropic/claude-3-opus"]
    min_confidence: 0.7
  analytical:
    providers: ["openai/gpt-4", "openai/gpt-4-turbo"]
    min_confidence: 0.6
  coding:
    providers: ["deepseek/deepseek-coder", "openai/gpt-4"]
```

### 5. Cost-Aware Routing

**Automatically select cheapest provider** meeting quality requirements.

```bash
curl -X POST http://localhost:8080/v1/infer \
  -H "Content-Type: application/json" \
  -d '{
    "model": "auto",
    "messages": [{"role": "user", "content": "Simple Q&A"}],
    "optimization": "cost",
    "min_quality_score": 0.7
  }'
```

**Selection Logic:**
```
1. Filter providers by:
   - Supports requested features
   - Quality score >= min_quality_score
   - Latency <= latency_budget (if specified)

2. Sort by cost (ascending)

3. Select cheapest provider
```

**Cost Comparison (per 1K tokens):**
```

Claude Haiku:     $0.0025
GPT-4 Turbo:      $0.01
Claude Opus:      $0.015
GPT-4:            $0.03    Most expensive
```

### Thompson Sampling Updates

```go
// Update provider scores after each request
func (ar *AdaptiveRouter) UpdateReward(providerID string, latencyMs int, cost float64, success bool) {
    provider := ar.backends[providerID]

    // Calculate reward (0.0 - 1.0)
    reward := calculateCompositeReward(latencyMs, cost, success)

    if reward >= ar.config.SuccessThreshold {
        // Increment α (successes)
        provider.Alpha += 1.0
    } else {
        // Increment β (failures)
        provider.Beta += 1.0
    }

    // Update running averages
    provider.AvgLatency = updateAverage(provider.AvgLatency, latencyMs)
    provider.AvgCost = updateAverage(provider.AvgCost, cost)
}
```

## Circuit Breaker & Failover

Automatic provider health monitoring and failover.

### Circuit Breaker States

```
┌──────────┐
│  CLOSED  │  Normal operation
└──────────┘
     │
     │ 3+ failures
     ↓
┌──────────┐
│   OPEN   │  All requests fail fast
└──────────┘
     │
     │ After 30s timeout
     ↓
┌──────────┐
│ HALF-OPEN│  Test with 1 request
└──────────┘
     │
     ├── Success → Back to CLOSED
     └── Failure → Back to OPEN
```

### Configuration

```yaml
# Circuit breaker settings
provider_health_check_interval_seconds: 60
provider_degraded_threshold_failures: 3
provider_circuit_breaker_timeout_seconds: 30
```

### Health Monitoring

```go
// Continuous health checks
func (ar *AdaptiveRouter) monitorHealth() {
    ticker := time.NewTicker(60 * time.Second)
    for range ticker.C {
        for _, backend := range ar.backends {
            err := backend.Provider.HealthCheck(ctx)
            if err != nil {
                backend.FailureCount++
                if backend.FailureCount >= 3 {
                    // Open circuit breaker
                    backend.CircuitBreakerOpen = true
                }
            } else {
                backend.FailureCount = 0
                backend.CircuitBreakerOpen = false
            }
        }
    }
}
```

## Best Practices

### When to Use Each Strategy

1. **Thompson Sampling**: General-purpose, production workloads
2. **Speculative Execution**: Real-time chat, interactive applications (Growth+)
3. **Council Mode**: High-stakes decisions, content generation (Growth+)
4. **Semantic Routing**: Heterogeneous workloads, cost optimization
5. **Cost-Aware**: Batch processing, budget-conscious applications
6. **Round Robin**: Testing, A/B comparisons
7. **Least Latency**: Latency-critical applications
8. **Least Load**: Even distribution, capacity management

### Performance Tips

1. **Enable caching** for semantic classification (3600s TTL)
2. **Set reasonable timeouts** (5s for first token)
3. **Monitor waste ratio** for speculative execution (&lt;30%)
4. **Use council mode sparingly** (higher cost and latency)
5. **Configure fallback providers** for each tier

### Cost Optimization

1. Start with **Cost-Aware Routing** for predictable workloads
2. Use **Speculative Execution** in latency mode (20% cost reduction)
3. Enable **auto-disable** for speculative when waste >30%
4. Route simple queries to **GPT-3.5** via semantic routing
5. Monitor **cost per request** metrics continuously

## Troubleshooting

### Issue: "All providers circuit breaker open"

**Solution:**
- Check provider API keys are valid
- Verify network connectivity to provider endpoints
- Review health check logs: `grep "HealthCheck" logs/`
- Manually reset circuit breaker: `POST /admin/circuit-breaker/{provider}/reset`

### Issue: "Speculative execution auto-disabled"

**Cause:** Waste ratio exceeded 30%

**Solution:**
- Review provider selection (are they too similar?)
- Increase diversity of providers in race
- Adjust mode to "balanced" or "cost"
- Check if one provider is significantly slower

### Issue: "Thompson Sampling always picks same provider"

**Cause:** Low exploration rate or one provider significantly better

**Solution:**
- Increase `bandit_exploration_rate` from 0.15 to 0.25
- Reset Thompson Sampling state: `POST /admin/routing/reset`
- Check if other providers are healthy
- Review reward weight configuration
