# Cognitive Advisor

## Overview

**Cognitive Advisor** is Schlep Engine's AI-native operational autonomy system that generates explainable policy recommendations by analyzing provider performance, telemetry, and historical patterns. It operates in shadow-only mode, producing proposals for human review rather than making autonomous changes.

The implementation is located in `/internal/cognitive/` and is fully operational in production environments.

## Key Features

### Shadow-Only Operation

- **No Live Mutations**: All recommendations are proposals only, never automatically applied
- **Human-in-the-Loop**: Requires explicit approval before any policy changes
- **Safety-First**: Multiple validation gates before proposal generation
- **Audit Trail**: Complete history of all proposals and decisions

### Multi-Signal Synthesis

Cognitive Advisor combines multiple data sources:

1. **Phase 11.1 RL Agent**: Policy suggestions from reinforcement learning
2. **Phase 11.2 Predictive Forecasts**: Future state predictions (integration ready)
3. **Real-Time Telemetry**: Current performance metrics and trends
4. **Historical Data**: Past performance patterns and trends

### Explainable Decisions

Every proposal includes:

- **Human-Readable Rationale**: Clear explanation of why the recommendation was made
- **Risk Assessment**: Quantified rollback risk and confidence scores
- **Evidence Links**: References to supporting data (RL outputs, simulations, telemetry)
- **Alternative Actions**: Other options considered and why they were rejected

## Safety Guarantees

The Cognitive Advisor implements multiple safety mechanisms:

### 1. Shadow-Only Mode

All recommendations are proposals only - never automatically executed:

```rust
// From policy_reasoner.rs
pub struct ReasonerConfig {
    pub enabled: bool,
    pub shadow_only: true, // ALWAYS true, never false
    pub output_dir: "experiments/cognitive",
    // ...
}
```

### 2. Confidence Gates

Proposals below 85% confidence are flagged for extra review:

```rust
if proposal.confidence_score < 0.85 {
    proposal.requires_human_review = true;
    proposal.review_reason = "Low confidence score";
}
```

### 3. Risk Thresholds

High-risk proposals (>15% rollback risk) trigger additional validation:

```rust
if proposal.risk_assessment.rollback_risk > 0.15 {
    proposal.requires_human_review = true;
    proposal.review_reason = "High rollback risk";
}
```

### 4. Drift Detection

Prevents excessive policy changes:

```rust
let drift_percentage = calculate_drift(&current_policy, &proposed_policy);
if drift_percentage > 5.0 {
    proposal.safety_assessment.drift_gate_passed = false;
}
```

### 5. Safety Priority

Critical states override RL suggestions:

```rust
if telemetry.error_rate > 0.10 {
    // Override RL, recommend immediate rollback
    return generate_emergency_rollback_proposal();
}
```

## Performance Analysis

### Degradation Detection

The advisor continuously monitors provider performance:

```go
func (a *Advisor) calculateDegradationScore(m *ProviderMetrics) float64 {
    // Weighted scoring:
    // - Error rate: 40%
    // - P95 latency: 30%
    // - P99 latency: 20%
    // - Thompson beta: 10%

    errorScore := m.ErrorRate * 0.4
    latencyScore := math.Min(m.P95Latency/5000.0, 1.0) * 0.3
    p99Score := math.Min(m.P99Latency/10000.0, 1.0) * 0.2
    betaScore := float64(m.ThompsonBeta) / float64(m.ThompsonAlpha+m.ThompsonBeta) * 0.1

    return errorScore + latencyScore + p99Score + betaScore
}
```

### Proposal Generation Criteria

Proposals are generated when:

1. **Significant Degradation**: Degradation score > 0.3
2. **Performance Gap**: >20% difference between best and worst providers
3. **Confidence Threshold**: Statistical significance (>100 requests per provider)
4. **Time Window**: Sustained degradation over 1+ hour

## Best Practices

### Review Process

1. **Daily Review**: Check pending proposals each morning
2. **Confidence Filtering**: Review high-confidence (>0.90) proposals first
3. **Risk Assessment**: Extra scrutiny for medium/high risk proposals
4. **Shadow Testing**: Deploy to staging before production
5. **Gradual Rollout**: Apply to 10% → 50% → 100% of traffic

## FAQ

### Does Cognitive Advisor make automatic changes?

No, it only generates proposals for human review. All changes require explicit approval.

### How often does analysis run?

Default: every 15 minutes. Configurable via `COGNITIVE_ANALYSIS_INTERVAL`.

### What happens if I reject all proposals?

The system continues generating proposals. Rejections are used to improve future recommendations.

### Can I customize the scoring weights?

Yes, degradation scoring weights are configurable in the advisor initialization.

### How is this different from Thompson Sampling?

Thompson Sampling makes real-time routing decisions. Cognitive Advisor generates policy improvement recommendations over longer time windows.
