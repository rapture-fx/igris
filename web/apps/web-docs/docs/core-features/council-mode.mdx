# Council Mode

## Overview

**Council Mode** is Schlep Engine's multi-agent consensus system that uses ensemble decision-making to improve routing decisions, validate proposals, and provide explainable recommendations. Multiple AI agents with different optimization priorities "vote" on routing decisions to find optimal consensus.

## Status

> **⚠️ Feature In Research**
>
> Council Mode is currently in active research in the `/labs/research/cognitive/` directory. This documentation describes the planned implementation and ongoing experiments.

## Concept

Instead of a single routing decision, Council Mode operates multiple specialized "council members" that each evaluate requests from different perspectives:

- **Speed Advocate**: Prioritizes latency reduction
- **Cost Optimizer**: Focuses on cost efficiency
- **Quality Guardian**: Ensures response quality
- **Reliability Monitor**: Emphasizes uptime and stability

These agents deliberate and reach consensus on the optimal provider selection.

### Experiment 3: Dynamic Agent Composition

Adjust council composition based on request type:

```python
def select_council_for_request(request):
    """Dynamically compose council based on request characteristics"""

    council = []

    # Always include cost optimizer
    council.append(agents["cost_optimizer"])

    # For latency-sensitive requests
    if request.max_latency_ms < 200:
        council.append(agents["speed_advocate"])

    # For quality-critical requests
    if request.min_quality_score > 0.9:
        council.append(agents["quality_guardian"])

    # For high-reliability needs
    if request.max_error_rate < 0.01:
        council.append(agents["reliability_monitor"])

    return council
```

## Research Challenges

### Computational Overhead

Running multiple agents adds latency:

**Mitigation Strategies:**
- Parallel agent evaluation
- Caching agent decisions for similar requests
- Agent pruning based on request type

### Agent Bias

Agents may develop biases:

**Mitigation Strategies:**
- Regular weight re-initialization
- Diversity metrics in agent composition
- Bias detection and correction

### Consensus Deadlock

Agents may not reach agreement:

**Mitigation Strategies:**
- Fallback to Thompson Sampling
- Tiebreaker agent with final say
- Timeout with default decision

Council Mode augments Thompson Sampling, not replaces it:

```

Council Mode: Slow, multi-objective deliberation

Use Together:
- Thompson for 90% of traffic (fast path)
- Council for 10% where uncertainty is high (deep analysis)
```

## FAQ

### Is Council Mode slower than Thompson Sampling?

Yes, typically 10-50ms overhead for agent evaluation and voting. This is why it's designed for selective use, not all traffic.

### How many agents are optimal?

Research ongoing, but 4-6 agents seems to be the sweet spot. More agents = diminishing returns vs overhead.

### Can I add custom agents?

Planned for Phase 5. You'll be able to define custom agents with specific optimization functions.

### Does this work in EscapeVector Mode?

Yes, council votes can use cached parameters just like Thompson Sampling does.

### What if agents disagree?

The consensus mechanism (weighted vote, rank aggregation, etc.) resolves disagreement. In case of deadlock, fallback to Thompson Sampling.
