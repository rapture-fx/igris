# Runtime Fleet

Overture can manage a fleet of Igris Runtime instances. Registered instances appear in your fleet dashboard, receive configuration pushes, and send telemetry back to Overture for centralized monitoring.

---

## Overview

A fleet is a collection of Runtime instances that Overture knows about and can route requests to. Each instance registers with Overture, sends periodic heartbeats, and can be configured remotely.

```
Overture (Control Plane)
    │
    ├── Fleet Registry
    │     ├── edge-device-01  (online, healthy)
    │     ├── edge-device-02  (online, healthy)
    │     └── edge-device-03  (offline, last seen 4m ago)
    │
    └── Routing Engine
          └── can route requests to any registered runtime
```

---

## Registering a Runtime Instance

Each Runtime instance calls the registration endpoint when it starts:

```bash
# From your Runtime instance (or via setup script):
curl -X POST https://overture.igrisinertial.com/api/v1/runtime/register \
  -H "Authorization: Bearer $IGRIS_API_KEY" \
  -H "Content-Type: application/json" \
  -d '{
    "name": "edge-device-01",
    "endpoint": "http://192.168.1.100:8080",
    "location": "factory-floor-a",
    "tags": ["production", "robotics"]
  }'
```

```json
{
  "runtime_id": "rt_abc123",
  "name": "edge-device-01",
  "status": "registered",
  "registered_at": "2026-03-01T10:00:00Z"
}
```

Save the `runtime_id` — it's used for configuration and monitoring calls.

---

## Heartbeat

Registered instances send heartbeats to signal they are alive. Runtime handles this automatically when configured with your API key. Instances that miss heartbeats are marked offline in the fleet dashboard.

```bash
curl -X POST https://overture.igrisinertial.com/api/v1/runtime/heartbeat \
  -H "Authorization: Bearer $IGRIS_API_KEY" \
  -H "Content-Type: application/json" \
  -d '{
    "runtime_id": "rt_abc123",
    "status": "healthy",
    "metrics": {
      "requests_last_minute": 12,
      "local_model_loaded": true,
      "disk_free_gb": 48.2
    }
  }'
```

## Listing Fleet Members

View all registered instances:

```bash
curl https://overture.igrisinertial.com/api/v1/runtime/list \
  -H "Authorization: Bearer $IGRIS_API_KEY"
```

```json
{
  "runtimes": [
    {
      "runtime_id": "rt_abc123",
      "name": "edge-device-01",
      "status": "online",
      "endpoint": "http://192.168.1.100:8080",

      "status": "offline",

  ]
}
```

## Fleet Health

Get an aggregated health view across all instances:

```bash
curl https://overture.igrisinertial.com/api/fleet/health \
  -H "Authorization: Bearer $IGRIS_API_KEY"
```

```json
{
  "total": 3,
  "online": 2,
  "offline": 1,
  "degraded": 0,
  "last_updated": "2026-03-01T14:22:00Z"
}
```

## Sending Configuration to Instances

Push configuration to a specific instance:

```bash
curl -X PUT https://overture.igrisinertial.com/api/fleet/agents/rt_abc123/config \
  -H "Authorization: Bearer $IGRIS_API_KEY" \
  -H "Content-Type: application/json" \
  -d '{
    "local_fallback": {
      "enabled": true,
      "model_path": "models/phi-3-mini-4k-instruct-q4.gguf"
    },
    "rate_limiting": {
      "requests_per_minute": 100
    }
  }'
```

Runtime instances poll for configuration updates periodically. Configuration is applied without restarting the process.

---

## Telemetry

Fleet instances send execution telemetry back to Overture. This includes per-request timing, token usage, provider selection, and error events.

View telemetry for a specific instance:

```bash
curl https://overture.igrisinertial.com/api/fleet/agents/rt_abc123 \
  -H "Authorization: Bearer $IGRIS_API_KEY"
```

Telemetry feeds into the Overture observability dashboard. Fleet-wide metrics are available at `/api/fleet/health`.

---

## Routing to Fleet Instances

Once instances are registered, configure Overture's routing policy to include them:

```json
{
  "routing": {
    "primary": ["openai", "anthropic"],
    "fallback": [
      "runtime:rt_abc123",
      "runtime:rt_def456"
    ]
  }
}
```

Overture will route requests to registered Runtime instances as part of its normal provider selection, including local fallback logic.
