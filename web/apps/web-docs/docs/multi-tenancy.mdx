# Multi-Tenancy Guide

Schlep Engine provides complete tenant isolation with BYOK (Bring Your Own Key), per-tenant configuration, and usage tracking.

## Overview

Multi-tenancy in Schlep Engine ensures:

- **Complete Isolation**: Tenant data never mixes
- **BYOK Support**: Each tenant uses their own provider API keys
- **Per-Tenant Limits**: Request limits, rate limits, and budgets per tier
- **Custom Configuration**: Tenant-specific routing policies and features
- **Usage Tracking**: Detailed cost and performance metrics per tenant

## Tenant Model

### Tenant Schema

```sql
CREATE TABLE tenants (
    tenant_id UUID PRIMARY KEY DEFAULT gen_random_uuid(),
    name VARCHAR(255) NOT NULL,
    tier VARCHAR(50) NOT NULL CHECK (tier IN ('trial', 'developer', 'growth', 'scale')),
    email VARCHAR(255) NOT NULL,
    created_at TIMESTAMP DEFAULT NOW(),
    updated_at TIMESTAMP DEFAULT NOW(),
    metadata JSONB,

    -- Usage tracking
    requests_this_month INTEGER DEFAULT 0,
    requests_reset_at TIMESTAMP DEFAULT NOW(),

    -- Budget
    monthly_budget_usd DECIMAL(10,2),
    budget_alert_threshold DECIMAL(3,2) DEFAULT 0.80,

    -- Status
    status VARCHAR(50) DEFAULT 'active',
    suspended_at TIMESTAMP
);
```

### Provider Registry Schema

```sql
CREATE TABLE provider_registry (
    registry_id UUID PRIMARY KEY DEFAULT gen_random_uuid(),
    tenant_id UUID REFERENCES tenants(tenant_id) ON DELETE CASCADE,
    provider_id VARCHAR(100) NOT NULL,
    api_key_encrypted TEXT NOT NULL,
    config JSONB,
    created_at TIMESTAMP DEFAULT NOW(),
    updated_at TIMESTAMP DEFAULT NOW(),

    UNIQUE(tenant_id, provider_id)
);
```

### API Keys Schema

```sql
CREATE TABLE api_keys (
    key_id UUID PRIMARY KEY DEFAULT gen_random_uuid(),
    tenant_id UUID REFERENCES tenants(tenant_id) ON DELETE CASCADE,
    key_hash VARCHAR(64) NOT NULL,  -- SHA-256 hash
    key_preview VARCHAR(20) NOT NULL,  -- First/last characters for display
    name VARCHAR(255),
    created_at TIMESTAMP DEFAULT NOW(),
    last_used_at TIMESTAMP,
    expires_at TIMESTAMP,

    UNIQUE(key_hash)
);
```

## Tenant Isolation

### Request Scoping

All requests are automatically scoped to the tenant:

```go
// Extract tenant from API key
func AuthMiddleware(c *fiber.Ctx) error {
    apiKey := extractAPIKey(c)

    // Query database for tenant
    tenant, err := db.GetTenantByAPIKey(apiKey)
    if err != nil {
        return c.Status(401).JSON(fiber.Map{"error": "Invalid API key"})
    }

    // Attach tenant context
    c.Locals("tenant_id", tenant.TenantID)
    c.Locals("tenant_tier", tenant.Tier)

    return c.Next()
}
```

### Data Access Control

All database queries are tenant-scoped:

```go
// Get tenant-specific providers
func GetProviders(tenantID string) ([]Provider, error) {
    var providers []Provider
    err := db.Where("tenant_id = ?", tenantID).Find(&providers).Error
    return providers, err
}

// Get tenant-specific requests
func GetRequests(tenantID string, since time.Time) ([]Request, error) {
    var requests []Request
    err := db.Where("tenant_id = ? AND created_at >= ?", tenantID, since).
        Find(&requests).Error
    return requests, err
}
```

### PostgreSQL Row-Level Security

```sql
-- Enable RLS on tenants table
ALTER TABLE tenants ENABLE ROW LEVEL SECURITY;

-- Policy: Tenants can only see their own data
CREATE POLICY tenant_isolation ON tenants
    FOR ALL
    USING (tenant_id = current_setting('app.tenant_id')::uuid);

-- Set tenant context in session
SET app.tenant_id = 'tenant_abc123';
```

## Tier-Based Limits

### Limit Enforcement

```go
// Middleware: Enforce tier limits
func TierGatingMiddleware(c *fiber.Ctx) error {
    tenantID := c.Locals("tenant_id").(string)
    tenantTier := c.Locals("tenant_tier").(string)

    // Load tier config
    tierConfig := config.GetTierConfig(tenantTier)

    // Check request count
    requestCount := getRequestCount(tenantID)
    if requestCount >= tierConfig.Limits.MaxRequestsPerMonth {
        return c.Status(429).JSON(fiber.Map{
            "error": "Monthly request limit exceeded",
            "limit": tierConfig.Limits.MaxRequestsPerMonth,
            "current": requestCount,
        })
    }

    // Check rate limit
    if !checkRateLimit(tenantID, tierConfig.Limits.MaxRequestsPerSecond) {
        return c.Status(429).JSON(fiber.Map{
            "error": "Rate limit exceeded",
            "limit": tierConfig.Limits.MaxRequestsPerSecond,
        })
    }

    // Check feature access
    if c.Params("feature") == "speculative" && !tierConfig.Features.SpeculativeExecution {
        return c.Status(403).JSON(fiber.Map{
            "error": "Speculative execution requires Growth tier or higher",
        })
    }

    return c.Next()
}
```

```promql
sum by (provider) (inference_requests_total{tenant_id="tenant_abc123"})
```

## Best Practices

### Security
1. **Never log API keys** in plaintext
2. **Use SHA-256 hashing** for key storage
3. **Enable key expiration** (recommended: 365 days)
4. **Rotate keys regularly** (every 90 days)
5. **Monitor key usage** for anomalies

### Performance
1. **Cache tenant configuration** (Redis, TTL: 300s)
2. **Use connection pooling** per tenant
3. **Batch request counting** (update every 60s)
4. **Index tenant_id columns** for fast queries

### Cost Control
1. **Set budget alerts** at 80% and 90%
2. **Review usage weekly** for trends
3. **Enable hard caps** for production (Scale tier)
4. **Monitor waste ratio** for speculative execution
