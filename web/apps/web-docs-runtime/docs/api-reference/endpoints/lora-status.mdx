# GET /v1/lora/status

Returns the status of on-device LoRA adapter training and the currently loaded adapter. Use this endpoint to monitor automatic fine-tuning progress.

---

## Request

```bash
curl http://localhost:8080/v1/lora/status \
  -H "Authorization: Bearer YOUR_API_KEY"
```

---

## Response

### When no adapter is loaded

```json
{
  "adapter_loaded": false,
  "training": {
    "status": "idle",
    "requests_since_last_training": 47,
    "training_trigger_threshold": 100
  }
}
```

### When training is in progress

```json
{
  "adapter_loaded": true,
  "current_adapter": {
    "path": "adapters/lora-v3.safetensors",
    "rank": 16,
    "trained_at": "2026-02-28T14:21:00Z",
    "training_samples": 100,
    "size_bytes": 52428800
  },
  "training": {
    "status": "training",
    "started_at": "2026-03-01T09:15:30Z",
    "progress_pct": 62,
    "requests_since_last_training": 0,
    "training_trigger_threshold": 100
  }
}
```

### When adapter is loaded and idle

```json
{
  "adapter_loaded": true,
  "current_adapter": {
    "path": "adapters/lora-v4.safetensors",
    "rank": 16,
    "trained_at": "2026-03-01T09:22:14Z",
    "training_samples": 200,
    "size_bytes": 52428800
  },
  "training": {
    "status": "idle",
    "requests_since_last_training": 23,
    "training_trigger_threshold": 100
  }
}
```

---

## Fields

| Field | Type | Description |
|---|---|---|
| `adapter_loaded` | boolean | Whether a LoRA adapter is currently applied to the base model |
| `current_adapter.path` | string | Filesystem path to the active adapter |
| `current_adapter.rank` | integer | LoRA rank used during training |
| `current_adapter.trained_at` | string | ISO 8601 timestamp of when this adapter was trained |
| `current_adapter.training_samples` | integer | Number of request/response pairs used to train the adapter |
| `current_adapter.size_bytes` | integer | Adapter file size in bytes |
| `training.status` | string | `"idle"`, `"training"`, or `"error"` |
| `training.started_at` | string | ISO 8601 timestamp when current training run started |
| `training.progress_pct` | integer | Training progress (0–100) when `status` is `"training"` |
| `training.requests_since_last_training` | integer | Requests accumulated since the last training run |
| `training.training_trigger_threshold` | integer | Requests needed to trigger the next automatic training run |

---

## Training Lifecycle

1. Engine accumulates request/response pairs locally (default threshold: 100)
2. When threshold is reached, training triggers automatically
3. A new LoRA adapter is trained using QLoRA (4-bit quantized)
4. On completion, the new adapter hot-swaps in without restarting
5. Counter resets and accumulation begins again

All training data remains on device. Adapters are encrypted with a device-specific key.
