# Robot Navigation with Behavior Trees

Combine behavior trees, Nav2, and simulation to build autonomous robot navigation.

---

## Overview

This tutorial walks through a complete robot navigation pipeline:

1. Define a navigation behavior tree in YAML
2. Connect to Nav2 through the runtime
3. Run the tree in a simulated environment
4. Handle navigation failures with fallback logic

**Prerequisites:**

- Igris Runtime running with ROS2 integration enabled
- ROS2 Humble or later installed
- Nav2 stack configured
- A simulation environment (Gazebo or similar)

---

## Step 1: Enable ROS2 and Nav2 in Runtime

Add the following to your `config.json5`:

```json5
{
  server: {
    host: "0.0.0.0",
    port: 8080
  },

  ros2: {
    enabled: true,
    node_name: "igris_runtime_node",
    enable_nav2: true,
    nav2_action_server: "/navigate_to_pose",
    map_frame: "map",
    robot_base_frame: "base_link"
  },

  local_fallback: {
    enabled: true,
    model_path: "models/phi-3-mini-4k-instruct-q4.gguf"
  }
}
```

Start the runtime:

```bash
igris-runtime serve --config config.json5
```

You should see:

```
ROS2 node initialized: igris_runtime_node
Nav2 action client connected: /navigate_to_pose
```

## Step 2: Define the Navigation Behavior Tree

Create `warehouse_nav.yaml`:

```yaml
name: warehouse_navigation
type: sequence
children:
  # Phase 1: System checks
  - name: system_checks
    type: sequence
    children:
      - name: check_battery
        type: condition
        condition: blackboard_gte
        params:
          key: battery_level
          value: 15

      - name: check_nav2_ready
        type: condition
        condition: ros2_service_available
        params:
          service: "/navigate_to_pose"

      - name: check_localization
        type: condition
        condition: ros2_topic_active
        params:
          topic: "/amcl_pose"
          timeout_secs: 5

  # Phase 2: Navigate to pickup zone
  - name: go_to_pickup
    type: action
    action: nav2_navigate
    params:
      x: 12.5
      y: 3.0
      theta: 1.57
      label: "Pickup Zone"
      timeout_secs: 60

  # Phase 3: Perform pickup
  - name: pickup_sequence
    type: sequence
    children:
      - name: align_to_shelf
        type: action
        action: nav2_navigate
        params:
          x: 12.5
          y: 3.2
          theta: 1.57
          label: "Shelf Alignment"
          timeout_secs: 15

      - name: activate_gripper
        type: action
        action: ros2_publish
        params:
          topic: "/gripper/command"
          message_type: "std_msgs/msg/String"
          data: '{"action": "close"}'

      - name: confirm_grip
        type: condition
        condition: ros2_topic_value
        params:
          topic: "/gripper/status"
          field: "gripping"
          value: true
          timeout_secs: 5

  # Phase 4: Navigate to drop-off
  - name: go_to_dropoff
    type: action
    action: nav2_navigate
    params:
      x: 2.0
      y: 8.0
      theta: 0.0
      label: "Drop-off Zone"
      timeout_secs: 60

  # Phase 5: Release
  - name: release_object
    type: action
    action: ros2_publish
    params:
      topic: "/gripper/command"
      message_type: "std_msgs/msg/String"
      data: '{"action": "open"}'

  - name: mark_complete
    type: action
    action: set_blackboard
    params:
      key: mission_status
      value: "delivery_complete"
```

This tree performs a full pick-and-place mission: check systems, navigate to pickup, grab an object, navigate to drop-off, and release.

## Step 3: Run in Simulation

### Launch the Simulation

Start your Gazebo simulation with Nav2:

```bash
# Terminal 1: Launch simulation world
ros2 launch igris_sim warehouse_world.launch.py

# Terminal 2: Launch Nav2 stack
ros2 launch nav2_bringup navigation_launch.py \
  use_sim_time:=True \
  map:=/path/to/warehouse_map.yaml

# Terminal 3: Start Igris Runtime
igris-runtime serve --config config.json5
```

### Execute the Navigation Tree

**Python:**

```python
from igris import Runtime

runtime = Runtime(base_url="http://localhost:8080")

# Pre-populate blackboard with sensor state
result = runtime.execute_btree(
    tree="warehouse_navigation",
    tree_yaml=open("warehouse_nav.yaml").read(),
    max_ticks=5000,
    timeout_secs=300,
    blackboard={
        "battery_level": 92,
    },
)

print(f"Mission status: {result.status}")
print(f"Delivery: {result.blackboard.get('mission_status')}")
print(f"Total ticks: {result.tick_count}")
print(f"Duration: {result.duration_secs:.1f}s")
```

**JavaScript:**

```typescript
import { Runtime } from '@igris-inertial/sdk';
import { readFileSync } from 'fs';

const runtime = new Runtime({ baseUrl: 'http://localhost:8080' });

const result = await runtime.executeBtree({
  tree: 'warehouse_navigation',
  treeYaml: readFileSync('warehouse_nav.yaml', 'utf-8'),
  maxTicks: 5000,
  timeoutSecs: 300,
  blackboard: {
    battery_level: 92,
  },
});

console.log(`Mission status: ${result.status}`);
console.log(`Delivery: ${result.blackboard.mission_status}`);
```

## Step 4: Handle Navigation Failures

Navigation can fail for many reasons: obstacles, localization loss, battery depletion. Wrap navigation actions in fault-tolerant patterns.

### Retry with Re-localization

If navigation fails, re-localize and try again:

```yaml
name: robust_navigate
type: selector
children:
  # Attempt 1: Direct navigation
  - name: direct_navigate
    type: action
    action: nav2_navigate
    params:
      x: 12.5
      y: 3.0
      theta: 1.57
      timeout_secs: 60

  # Attempt 2: Re-localize, then retry
  - name: relocalize_and_retry
    type: sequence
    children:
      - name: trigger_relocalization
        type: action
        action: ros2_service_call
        params:
          service: "/reinitialize_global_localization"
          timeout_secs: 10

      - name: wait_for_localization
        type: action
        action: wait
        params:
          duration_secs: 5

      - name: retry_navigate
        type: action
        action: nav2_navigate
        params:
          x: 12.5
          y: 3.0
          theta: 1.57
          timeout_secs: 90

  # Attempt 3: Clear costmap and retry
  - name: clear_and_retry
    type: sequence
    children:
      - name: clear_costmaps
        type: action
        action: ros2_service_call
        params:
          service: "/local_costmap/clear_entirely_local_costmap"
          timeout_secs: 5

      - name: final_navigate
        type: action
        action: nav2_navigate
        params:
          x: 12.5
          y: 3.0
          theta: 1.57
          timeout_secs: 120

  # All attempts failed
  - name: navigation_failed
    type: action
    action: set_blackboard
    params:
      key: nav_status
      value: "failed_all_attempts"
```

### Battery-Aware Navigation

Add a battery watchdog that aborts the mission and returns to the charging station if battery drops too low:

```yaml
name: battery_aware_mission
type: sequence
children:
  - name: battery_watchdog
    type: decorator
    decorator: condition_guard
    condition:
      type: condition
      condition: blackboard_gte
      params:
        key: battery_level
        value: 15
    child:
      name: main_mission
      type: sequence
      children:
        - name: go_to_target
          type: action
          action: nav2_navigate
          params:
            x: 12.5
            y: 3.0
            theta: 1.57
            timeout_secs: 60

        - name: perform_task
          type: action
          action: scan_area
          params:
            radius: 2.0

  # If battery guard triggers, return to charger
  - name: emergency_return
    type: action
    action: nav2_navigate
    params:
      x: 0.0
      y: 0.0
      theta: 0.0
      label: "Charging Station"
      timeout_secs: 120
```

### LLM-Assisted Recovery

When standard recovery fails, ask the LLM for an alternative route:

```yaml
name: llm_assisted_navigation
type: selector
children:
  - name: standard_navigate
    type: decorator
    decorator: retry
    max_attempts: 2
    child:
      name: navigate_direct
      type: action
      action: nav2_navigate
      params:
        x: 12.5
        y: 3.0
        theta: 1.57
        timeout_secs: 60

  - name: llm_reroute
    type: sequence
    children:
      - name: set_context
        type: action
        action: set_blackboard
        params:
          key: nav_failure_context
          value: >
            Navigation to (12.5, 3.0) failed twice.
            Current position is unknown. The robot is in a warehouse
            environment. Suggest an alternative approach with
            intermediate waypoints.

      - name: ask_llm
        type: llm_node
        prompt_key: nav_failure_context
        output_key: reroute_plan
        system_prompt: |
          You are a robot navigation planner. Output a JSON behavior tree
          with intermediate waypoints to reach the target. Use only
          nav2_navigate actions.

      - name: execute_reroute
        type: subtree_loader
        plan_key: reroute_plan
```

## Monitoring Navigation

### Check Navigation Status

```python
from igris import Runtime

runtime = Runtime(base_url="http://localhost:8080")

# Get current execution state
status = runtime.btree_status()
print(f"Active tree: {status.tree_name}")
print(f"Current node: {status.current_node}")
print(f"Tick count: {status.tick_count}")
print(f"Blackboard: {status.blackboard}")
```

### Subscribe to Navigation Events

```python
for event in runtime.btree_events(stream=True):
    if event.type == "node_status_change":
        print(f"Node '{event.node_name}' changed to {event.status}")
    elif event.type == "nav2_feedback":
        print(f"Nav2 progress: {event.distance_remaining:.2f}m remaining")
    elif event.type == "nav2_result":
        print(f"Nav2 result: {event.result}")
```
