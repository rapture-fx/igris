# API Reference

Igris exposes two API surfaces: the **cloud API** at `overture.igrisinertial.com`, and the **local engine API** on each runtime instance (default `http://localhost:8080`). They are separate services with different endpoints.

---

## Authentication

All cloud API requests require a Bearer token:

```bash
curl https://overture.igrisinertial.com/v1/chat/completions \
  -H "Authorization: Bearer YOUR_API_KEY" \
  -H "Content-Type: application/json" \
  -d '{"model": "gpt-4", "messages": [{"role": "user", "content": "Hello"}]}'
```

## Inference

### POST /v1/chat/completions

OpenAI-compatible chat completion with automatic multi-provider routing.

**Request:**
```json
{
  "model": "gpt-4",
  "messages": [
    {"role": "system", "content": "You are a helpful assistant."},
    {"role": "user", "content": "Hello"}
  ],
  "provider_preference": ["anthropic", "openai"]
}
```

| Field | Type | Description |
|---|---|---|
| `model` | string | Model name (passed to the selected provider) |
| `messages` | array | Standard OpenAI messages array |
| `provider_preference` | string[] | Optional ordered list of providers to try |

**Response:** Standard OpenAI `chat.completion` object. Fallback information is returned in the `X-Igris-Fallback-Count` response header.

### GET /v1/models

List available models across your configured providers.

### GET /v1/providers/stats

Current health and performance statistics for your configured providers.

## Routing Analytics

All routing endpoints require authentication.

### Read-only analytics

| Endpoint | Description |
|---|---|
| `GET /v1/routing/stats` | Total requests, avg latency, per-provider breakdown |
| `GET /v1/routing/leaderboard` | Providers ranked by request volume and avg latency |
| `GET /v1/routing/recent` | Last 20 requests with provider and latency |

Response for `GET /v1/routing/stats`:
```json
{
  "total_requests": 1842,
  "avg_latency_ms": 312.5,
  "provider_breakdown": [
    { "provider": "anthropic", "count": 1204, "avg_latency_ms": 287.1 },
    { "provider": "openai",    "count": 638,  "avg_latency_ms": 361.4 }
  ]
}
```

### Routing configuration (POST)

These endpoints persist routing settings per tenant. All return `{"saved": true}`.

| Endpoint | What it saves |
|---|---|
| `POST /v1/routing/strategy` | Active routing strategy (thompson-sampling, cost-optimized, etc.) |
| `POST /v1/routing/speculative` | Speculative execution settings |
| `POST /v1/routing/council` | Council mode settings (providers, chairman model) |
| `POST /v1/routing/shadow` | Shadow mode settings |
| `POST /v1/routing/provider_weights` | Manual provider weight overrides |

Example — set routing strategy:
```bash
curl -X POST https://overture.igrisinertial.com/v1/routing/strategy \
  -H "Authorization: Bearer YOUR_API_KEY" \
  -H "Content-Type: application/json" \
  -d '{"strategy": "thompson-sampling", "fallback_chain": ["anthropic", "openai", "local"]}'
```

## Execution Runs

These endpoints manage the lifecycle of execution runs. All require authentication.

### GET /v1/execution/runs

List execution runs for your tenant.

| Query param | Description |
|---|---|
| `limit` | Max results (default 20, max 200) |
| `sort` | `created_at:asc` or `created_at:desc` (default: desc) |
| `status` | Filter by status: `PAUSED`, `RUNNING`, `CANCELLED`, `COMPLETED`, `REJECTED` |

```bash
curl "https://overture.igrisinertial.com/v1/execution/runs?status=PAUSED&limit=50" \
  -H "Authorization: Bearer YOUR_API_KEY"
```

Response:
```json
[
  {
    "id": "exec-01HXYZ",
    "agent_id": "agent-abc",
    "device_id": "runtime-01",
    "started_at": "2026-03-01T12:00:00Z",
    "duration_ms": 1240,
    "status": "PAUSED",
    "has_violation": false,
    "pause_reason": "human_review_required",
    "prompt_preview": "Evaluate whether to initiate..."
  }
]
```

### POST /v1/execution/runs/:id/pause

Pause a running execution. Returns 404 if the run is already in a terminal state (CANCELLED, COMPLETED, violation).

```bash
curl -X POST https://overture.igrisinertial.com/v1/execution/runs/exec-01HXYZ/pause \
  -H "Authorization: Bearer YOUR_API_KEY"
# → {"status": "PAUSED"}
```

### POST /v1/execution/runs/:id/resume

Resume a paused execution. Only transitions runs in `PAUSED` state.

```bash
curl -X POST https://overture.igrisinertial.com/v1/execution/runs/exec-01HXYZ/resume \
  -H "Authorization: Bearer YOUR_API_KEY"
# → {"status": "RUNNING"}
```

### POST /v1/execution/runs/:id/cancel

Cancel a run. Irreversible — transitions to `CANCELLED`. Returns 404 if already cancelled or completed.

### POST /v1/execution/runs/:id/replay

Clone a completed run and start a new execution from the same agent and device.

```bash
curl -X POST https://overture.igrisinertial.com/v1/execution/runs/exec-01HXYZ/replay \
  -H "Authorization: Bearer YOUR_API_KEY"
# → {"status": "replayed", "new_execution_id": "exec-01HABC"}
```

### POST /v1/execution/runs/:id/approve

Human-in-the-loop approval. Transitions a `PAUSED` run to `RUNNING`. Records approver identity and timestamp.

```bash
curl -X POST https://overture.igrisinertial.com/v1/execution/runs/exec-01HXYZ/approve \
  -H "Authorization: Bearer YOUR_API_KEY"
# → {"status": "RUNNING", "approved": true}
```

### POST /v1/execution/runs/:id/reject

Human-in-the-loop rejection. Terminates the run with `REJECTED` status.

```bash
curl -X POST https://overture.igrisinertial.com/v1/execution/runs/exec-01HXYZ/reject \
  -H "Authorization: Bearer YOUR_API_KEY" \
  -H "Content-Type: application/json" \
  -d '{"reason": "unsafe_action_detected"}'
# → {"status": "REJECTED", "reason": "unsafe_action_detected"}
```

## Agents

### GET /v1/execution/agents

List agents derived from execution history. Includes recent executions and current mode flags.

```bash
curl https://overture.igrisinertial.com/v1/execution/agents \
  -H "Authorization: Bearer YOUR_API_KEY"
```

Response:
```json
[
  {
    "id": "agent-abc",
    "namespace": "default",
    "state": "IDLE",
    "last_run_at": "2026-03-01T12:00:00Z",
    "device_id": "runtime-01",
    "violation_count": 0,
    "shadow_mode": false,
    "reflection_mode": true,
    "council_mode": false,
    "cognitive_advisor_enabled": false,
    "recent_executions": [...]
  }
]
```

### PATCH /v1/agents/:id

Update mode flags for an agent. At least one field required.

```bash
curl -X PATCH https://overture.igrisinertial.com/v1/agents/agent-abc \
  -H "Authorization: Bearer YOUR_API_KEY" \
  -H "Content-Type: application/json" \
  -d '{"shadow_mode": true, "council_mode": true}'
```

| Field | Type | Description |
|---|---|---|
| `shadow_mode` | bool | Run a shadow copy alongside every real execution |
| `reflection_mode` | bool | Enable self-critiquing reflection after each execution |
| `council_mode` | bool | Use multi-provider consensus for this agent |
| `cognitive_advisor_enabled` | bool | Enable the cognitive routing advisor |

### GET /v1/agents/:id/bt-state

Returns the last 10 executions for an agent as a flat node list, suitable for tree visualization.

### GET /v1/agents/:id/bt-state/stream

Server-Sent Events stream of live BT tick snapshots from the connected runtime. Each event is a JSON object:

```
data: {"tick": 42, "status": "Running", "nodes": [...], "last_updated": "2026-03-01T12:00:01Z"}
```

Connect with `EventSource` and `withCredentials: true` (requires an active session cookie).

## Policies

### GET /v1/policies

Returns the active BT execution envelope limits for your tenant.

```bash
curl https://overture.igrisinertial.com/v1/policies \
  -H "Authorization: Bearer YOUR_API_KEY"
```

Response:
```json
{
  "allowed_node_types": ["Sequence", "Selector", "Parallel", "Decorator", "Action", "Condition", "RosTopicPublish", "RosTopicSubscribe", "RosServiceCall"],
  "max_action_nodes": 50,
  "max_depth": 10,
  "max_tool_calls": 20,
  "max_duration_secs": 300
}
```

Fields are omitted when no custom limit is set for your tenant (defaults apply).

### POST /v1/policies/assign

Assign a policy (by hash) to one or more agents.

```bash
curl -X POST https://overture.igrisinertial.com/v1/policies/assign \
  -H "Authorization: Bearer YOUR_API_KEY" \
  -H "Content-Type: application/json" \
  -d '{
    "agent_ids": ["agent-abc", "agent-def"],
    "policy_hash": "sha256:a3f9..."
  }'
# → {"status": "assigned", "agent_count": 2}
```

## On-Device Training (LoRA)

### GET /v1/lora/status

Proxied from the connected runtime. Returns current training status.

```bash
curl https://overture.igrisinertial.com/v1/lora/status \
  -H "Authorization: Bearer YOUR_API_KEY"
```

Response:
```json
{
  "enabled": true,
  "status": "Idle",
  "total_examples": 87,
  "request_counter": 87,
  "should_trigger": false,
  "last_started_at": 1743480000,
  "last_finished_at": 1743481800,
  "last_result": {
    "status": "Completed",
    "training_samples": 85,
    "training_time_secs": 312.4,
    "final_loss": 0.0821,
    "adapter_size_bytes": 4194304,
    "encrypted_adapter_path": "[encrypted-adapter-path]"
  }
}
```

If the runtime is unreachable, returns:
```json
{
  "enabled": false,
  "runtime_error": "runtime unreachable — check your runtime connection settings"
}
```

### POST /v1/lora/trigger

Manually trigger an on-device training run. Only valid when `enabled: true` and status is `Idle`.

```bash
curl -X POST https://overture.igrisinertial.com/v1/lora/trigger \
  -H "Authorization: Bearer YOUR_API_KEY"
# → {"triggered": true, "status": "Training"}
```

If training is already in progress: `{"triggered": false, "status": "Training"}`.

Aggregated request and cost summary for your tenant.

```bash
  -H "Authorization: Bearer YOUR_API_KEY"
```

| Query param | Values |
|---|---|
| `range` | `7d`, `30d` (default), `90d` |

```json
  "total_tokens_in": 1204800,
  "total_tokens_out": 384200,
```

### GET /models/usage/providers

Breakdown by provider for the selected range.

```bash
curl "https://overture.igrisinertial.com/models/usage/providers?range=7d" \
  -H "Authorization: Bearer YOUR_API_KEY"
```

## Provider Keys (Vault)

Manage your cloud provider API keys. All vault endpoints require authentication.

| Endpoint | Method | Description |
|---|---|---|
| `/v1/vault/keys` | GET | List all configured provider keys |
| `/v1/vault/keys` | POST | Add a provider key |
| `/v1/vault/keys/:provider` | GET | Get key details for a provider |
| `/v1/vault/keys/:provider` | DELETE | Remove a provider key |
| `/v1/vault/keys/:provider/rotate` | POST | Replace a key with a new one |
| `/v1/vault/keys/:provider/validate` | POST | Re-validate a key against the provider's API |

```bash
# Add a key

  -H "Authorization: Bearer YOUR_API_KEY" \
  -H "Content-Type: application/json" \
  -d '{"provider": "anthropic", "key": "YOUR_ANTHROPIC_KEY"}'
```

## Local Engine API

The runtime instance exposes a separate API at `http://localhost:8080` by default. This is distinct from the cloud API.

| Endpoint | Description |
|---|---|
| `GET /health` | Health check |
| `GET /metrics` | Prometheus metrics |
| `POST /v1/chat/completions` | Local chat completion |
| `GET /v1/lora/status` | On-device training status |
| `GET /v1/receipts` | List execution receipts (runtime-local storage) |
| `GET /v1/receipts/{id}` | Get a specific receipt |

> Execution receipts are stored locally on the runtime device. Nothing leaves your infrastructure unless you explicitly export them.

---

## Rate Limits

Requests to `/v1/chat/completions` are rate-limited per account. The limit is shown in response headers:

- `X-RateLimit-Limit` — requests allowed per window
- `X-RateLimit-Remaining` — requests remaining in current window

When the limit is exceeded, Igris returns HTTP 429.
