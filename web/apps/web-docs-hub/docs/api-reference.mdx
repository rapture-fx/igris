# API Reference

Igris exposes two API surfaces: the **cloud API** at `api.igrisinertial.com`, and the **local engine API** on each runtime instance (default `http://localhost:8080`). They are separate services with different endpoints.

---

## Authentication

All cloud API requests require a Bearer token:

```bash
curl https://api.igrisinertial.com/v1/chat/completions \
  -H "Authorization: Bearer YOUR_API_KEY" \
  -H "Content-Type: application/json" \
  -d '{"model": "gpt-4", "messages": [{"role": "user", "content": "Hello"}]}'
```

---

## Inference

### POST /v1/chat/completions

OpenAI-compatible chat completion with automatic multi-provider routing.

**Request:**
```json
{
  "model": "gpt-4",
  "messages": [
    {"role": "system", "content": "You are a helpful assistant."},
    {"role": "user", "content": "Hello"}
  ],
  "provider_preference": ["anthropic", "openai"]
}
```

| Field | Type | Description |
|---|---|---|
| `model` | string | Model name (passed to the selected provider) |
| `messages` | array | Standard OpenAI messages array |
| `provider_preference` | string[] | Optional ordered list of providers to try |

**Response:** Standard OpenAI `chat.completion` object. Fallback information is returned in the `X-Igris-Fallback-Count` response header.

### GET /v1/models

List available models across your configured providers.

### GET /v1/providers/stats

Current health and performance statistics for your configured providers.

## Routing Analytics

All routing endpoints require authentication.

| Endpoint | Description |
|---|---|
| `GET /v1/routing/stats` | Success rates, latency, and cost per provider |
| `GET /v1/routing/leaderboard` | Providers ranked by current Thompson Sampling score |
| `GET /v1/routing/recent` | Recent requests with routing decisions |
| `GET /v1/routing/speculative/status` | Speculative execution stats (24h window) |
| `GET /v1/routing/speculative/config` | Speculative execution configuration |
| `GET /v1/routing/speculative/analytics` | Speculative execution analytics |
| `POST /v1/routing/speculative/simulate` | Trigger a speculative simulation |

---

## Fleet (Runtime Instances)

These endpoints use API key authentication (not Bearer token) and are called by the runtime binary, not your application.

| Endpoint | Method | Description |
|---|---|---|
| `/api/v1/runtime/register` | POST | Register a runtime instance |
| `/api/v1/runtime/heartbeat` | POST | Send instance heartbeat |
| `/api/v1/runtime/deregister` | DELETE | Deregister an instance |
| `/api/v1/runtime/download` | GET | Download the runtime binary (authenticated) |

---

## Provider Keys

Provider API keys are managed through the console at [console.igrisinertial.com/settings/keys](https://console.igrisinertial.com/settings/keys). Keys are encrypted at rest and scoped to your account.

[Key Management →](/docs/key-management)

## Local Engine API

The runtime instance exposes a separate API at `http://localhost:8080` by default. This is distinct from the cloud API.

| Endpoint | Description |
|---|---|
| `GET /health` | Health check |
| `GET /metrics` | Prometheus metrics |
| `POST /v1/chat/completions` | Local chat completion |
| `GET /v1/receipts` | List execution receipts |
| `GET /v1/receipts/{id}` | Get a specific receipt |

---

## Rate Limits

Requests to `/v1/chat/completions` are rate-limited per account. The limit is shown in response headers:

- `X-RateLimit-Limit` — requests allowed per window
- `X-RateLimit-Remaining` — requests remaining in current window

When the limit is exceeded, Igris returns HTTP 429.
