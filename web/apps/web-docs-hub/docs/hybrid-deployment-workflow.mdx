# Hybrid Deployment Workflow

Use this workflow when you want one product experience for the customer while combining the hosted API with one or more local runtimes.

This is the right model when you want:

- hosted API access for the application layer
- local runtime execution close to the device or workload
- fleet visibility and rollout control
- a fallback path between hosted and local execution

---

## 1. Keep the application pointed at the hosted API

The application-facing base URL stays the same:

```text
https://overture.igrisinertial.com/v1
```

That keeps the customer contract unified even when runtimes are participating underneath.

## 2. Start runtimes with registration credentials

Hybrid deployment only works when the runtime can register successfully.

```bash
export IGRIS_LICENSE_KEY="YOUR_LICENSE_KEY"
export IGRIS_API_KEY="YOUR_IGRIS_API_KEY"
igris-runtime serve
```

## 3. Verify cloud and runtime access separately

Confirm both sides independently:

- hosted API calls succeed with your tenant API key
- the runtime answers `http://localhost:8080/v1/health`
- fleet visibility appears in the console when registration succeeds

## 4. Use fleet APIs for coordination

Once runtimes are participating, use the documented fleet-management routes and workflows for:

- runtime inventory
- config push
- OTA updates

Do not rebuild your own hidden coordination path when the product surface already supports it.

## 5. Separate hot-path traffic from provisioning traffic

Keep the hosted inference path and runtime management path conceptually separate:

- application traffic calls the hosted API
- operators and rollout systems manage runtimes and fleet operations

That keeps your architecture readable and avoids treating device management like ordinary inference traffic.

## Common Mistakes

- Pointing application clients directly at runtime coordination routes
- Expecting fleet visibility without valid `IGRIS_LICENSE_KEY` and `IGRIS_API_KEY`
- Mixing rollout traffic and customer inference traffic into the same operational path
