# Behavior Trees

Igris includes a production-grade behavior tree engine that combines deterministic control flow with LLM-powered adaptive reasoning. Use it to build agents that follow structured logic but can invoke an LLM when the situation requires judgment.

---

## Why Behavior Trees

Traditional behavior trees are deterministic: the same inputs always produce the same outputs. This is ideal for safety-critical systems but breaks down when the task requires language understanding or contextual reasoning.

Igris behavior trees let you mix both:
- **Deterministic nodes** — sequence, selector, condition, action — execute reliably and predictably
- **LLM nodes** — call a local or cloud model when the situation requires judgment

The result: agents that are auditable and safe by default, with AI where it adds value.

---

## Node Types

| Type | JSON `type` value | Behavior |
|---|---|---|
| `Sequence` | `"Sequence"` | Runs children left to right; stops on first failure |
| `Selector` | `"Selector"` | Runs children left to right; stops on first success |
| `Parallel` | `"Parallel"` | Runs all children concurrently |
| `Condition` | `"Condition"` | Returns success/failure based on a blackboard key check |
| `Action` | `"Action"` | Executes a named tool with optional args |
| `Decorator` | `"Decorator"` | Wraps a child node, modifying its return value |
| `RosTopicPublish` | `"RosTopicPublish"` | Publishes a message to a ROS2 topic |
| `RosTopicSubscribe` | `"RosTopicSubscribe"` | Reads from a ROS2 topic |
| `RosServiceCall` | `"RosServiceCall"` | Calls a ROS2 service |

## Behavior Tree Definitions API

Definitions are tenant-scoped and persisted in the coordination layer. Saving by the same name upserts the existing definition.

### GET /v1/bt/templates

Returns a list of built-in starter templates — no authentication required.

```bash
curl https://overture.igrisinertial.com/v1/bt/templates
```

Response:
```json
[
  {
    "id": "tpl-patrol",
    "name": "Patrol Loop",
    "description": "Repeating patrol with obstacle avoidance",
    "nodes": [...],
    "edges": [...]
  }
]
```

---

### GET /v1/bt/definitions

List all saved definitions for your tenant.

```bash
curl https://overture.igrisinertial.com/v1/bt/definitions \
  -H "Authorization: Bearer YOUR_API_KEY"
```

Response:
```json
[
  {
    "id": "def-01HXYZ",
    "name": "shutdown-guard",
    "description": "Temperature-triggered shutdown sequence",
    "created_at": "2026-03-01T12:00:00Z",
    "updated_at": "2026-03-01T12:00:00Z"
  }
]
```

---

### GET /v1/bt/definitions/:id

Fetch a single definition including full nodes and edges.

```bash
curl https://overture.igrisinertial.com/v1/bt/definitions/def-01HXYZ \
  -H "Authorization: Bearer YOUR_API_KEY"
```

---

### POST /v1/bt/definitions

Save or update a definition. Name is unique per tenant — posting the same name overwrites the existing definition.

```bash
curl -X POST https://overture.igrisinertial.com/v1/bt/definitions \
  -H "Authorization: Bearer YOUR_API_KEY" \
  -H "Content-Type: application/json" \
  -d '{
    "name": "shutdown-guard",
    "description": "Temperature-triggered shutdown sequence",
    "nodes": [
      { "id": "n1", "type": "Sequence", "label": "Root", "x": 300, "y": 50 },
      { "id": "n2", "type": "Condition", "label": "Check Temp", "x": 150, "y": 150 },
      { "id": "n3", "type": "Action", "label": "Shutdown", "x": 450, "y": 150 }
    ],
    "edges": [
      { "id": "e1", "source": "n1", "target": "n2" },
      { "id": "e2", "source": "n1", "target": "n3" }
    ]
  }'
```

| Field | Required | Description |
|---|---|---|
| `name` | Yes | Unique definition name within your tenant |
| `description` | No | Human-readable description |
| `nodes` | No | Array of node objects (defaults to `[]`) |
| `edges` | No | Array of edge objects (defaults to `[]`) |

Response: the saved definition with `id`, `created_at`, `updated_at`.

---

### DELETE /v1/bt/definitions/:id

Remove a definition permanently.

```bash
curl -X DELETE https://overture.igrisinertial.com/v1/bt/definitions/def-01HXYZ \
  -H "Authorization: Bearer YOUR_API_KEY"
```

Returns `204 No Content` on success. Returns `404` if the definition does not exist or belongs to a different tenant.

## Using the SDK

```typescript
import { Runtime, BehaviorTree, SequenceNode, ConditionNode, ActionNode } from '@igris/sdk';

const runtime = new Runtime({ localUrl: 'http://localhost:8080' });

const tree = BehaviorTree.fromJson(
  new SequenceNode('shutdown-guard', [
    new ConditionNode('check_temp', 'sensor.temperature', '80'),
    new ActionNode('shutdown', 'http_post', { url: 'http://localhost:9000/shutdown' }),
  ]).toJSON(),
  runtime,
);

const result = await tree.validate();
// { valid: true, root_type: 'Sequence' }
```

```python
from igris import Runtime, RuntimeConfig
from igris.btree import BehaviorTree, Sequence, Condition, Action

runtime = Runtime(RuntimeConfig(local_url="http://localhost:8080"))

tree = BehaviorTree.from_nodes(
    Sequence("shutdown-guard", [
        Condition("check_temp", key="sensor.temperature", expected=80),
        Action("shutdown", tool="http_post", args={"url": "http://localhost:9000/shutdown"}),
    ]),
    runtime,
)

result = tree.validate()
execution = tree.run(context={"sensor.temperature": 92})
print(execution["status"])  # 'success' | 'failure'
```

## Production Characteristics

- Trees are validated at deploy time — malformed trees are rejected before execution
- Each tick produces an execution receipt with the node path taken and outcome
- LLM node calls are subject to the same capability gates as any other tool call
- Trees can be hot-reloaded without restarting the engine
