# What is Igris?

Igris is reliable execution for AI agents that can change real systems.

Use it when an agent is about to do consequential work: touch infrastructure, call a payment API, mutate customer data, or otherwise change something outside the chat transcript. Direct model calls are still fine for ordinary prompting. Igris is for the actions that must survive failure, avoid blind retries, and remain inspectable after the fact.

## What you get

- **Run consequential actions durably.** Submit an Action once with a business idempotency key and a bound contract.
- **Recover from infrastructure failures.** If a runtime dies mid-flight, Igris can continue the managed run without you inventing a resume protocol.
- **Stop when the outcome is uncertain.** When the external effect cannot be known safely, Igris fails closed and requires operator reconciliation instead of guessing.

## The product lifecycle

```text
Action → Run → Recover → Reconcile when uncertain → Prove
```

1. **Action** — declare what the agent is allowed to do, as a typed contract bound to an executable target.
2. **Run** — submit one durable run with an explicit business idempotency key.
3. **Recover** — infrastructure failures are handled by the managed execution path; you wait and inspect, you do not manually poke checkpoints.
4. **Reconcile when uncertain** — unresolved external effects require an attributable operator assertion.
5. **Prove** — retrieve **Igris Run Proof**, a linked product view of distinct claims for that run.

## Who this is for

Engineers building coding, infrastructure, and operational agents that have permission to change external systems.

## Honest claim boundaries

Igris does **not** claim universal exactly-once execution against every external system.

- External duplicate-effect safety depends on supported idempotent targets.
- A Runtime receipt is not proof of external side-effect uniqueness.
- Action Protocol Evidence is not proof of managed execution.
- Igris Run Proof links distinct claims; it is not one universal cryptographic proof.
- Operator reconciliation is an attributable administrative assertion, not cryptographic proof of the external world.
- `eligible_linked` means server eligibility for evidence linkage, not signed run binding.
