# Safe execution for consequential coding-agent actions

Igris sits between a coding agent and operations such as deploy, migrate, and
publish. It gives those operations one durable product model:

1. **Action** — a named operation configured once by an operator.
2. **Run** — one durable attempt with policy, idempotency, approval, and
   explicit failure state.
3. **Proof** — an honest record of what Igris authorized, dispatched, observed,
   and verified.

If an external effect may have occurred but Igris cannot confirm it, the Run
requires exceptional **Reconciliation**. Igris does not blindly replay the
effect or label an operator assertion as cryptographic proof.

## The hosted-alpha wedge

- `deploy.staging`
- `deploy.production`
- `migrate.database`
- `publish.package`

Start with `deploy.staging`. Production deploy, database migration, and package
publication need stronger approval and target-specific safety controls; do not
infer readiness from their names alone.

## Proof boundaries

Signed records can establish integrity and provenance for events Igris
observed. They do not cryptographically prove that an external deployment,
migration, or publication was correct. See [Proof status](/docs/proof-status)
before making operational or compliance claims.
