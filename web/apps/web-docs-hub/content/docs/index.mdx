# Igris

Igris is a governed execution system for AI workloads. It runs across cloud, edge, and robotics hardware — every execution is bounded, verifiable, and resilient.

---

## One System, Three Surfaces

### Cloud

Igris coordinates inference across multiple cloud providers. It selects the best provider for each request, handles failover automatically, and tracks cost. Your application uses a single OpenAI-compatible API and stays oblivious to which provider responded.

### Edge

Igris runs on your hardware — a server, a Raspberry Pi, a Jetson — and serves local inference without internet access. The same API, the same governance model. Data stays on device.

### Robots

Igris connects to ROS2 ecosystems and executes AI-driven missions on physical hardware. Fleet coordination, safety limits, and execution receipts apply to robotic agents the same way they apply to cloud workloads.

---

## What Igris Guarantees

**Bounded execution.** Every request runs inside declared resource limits. Token budgets, time limits, tool restrictions, and capability gates are enforced at the engine level — not at the application layer, where they could be bypassed.

**Verifiable records.** Every execution produces a cryptographically signed receipt. Inputs, outputs, resource use, and capability grants are recorded and tamper-evident.

**Resilient inference.** When cloud providers are unavailable, Igris falls back to local on-device models automatically. Your application sees the same response format either way.

**Agent capabilities.** Igris runs reflection agents, planning agents, multi-agent swarms, and behavior trees. Tool use — HTTP, shell, filesystem — is governed and auditable.

## Platform Guarantees

**Bounded execution.** Resource limits, capability gates, and time budgets are enforced at the engine level.

**Verifiable records.** Signed execution envelopes cannot be altered after the fact. Every decision is recorded with a cryptographic seal.

**Resilient inference.** Cloud and local inference paths are equivalent from the application's perspective. Failover is automatic and transparent.
