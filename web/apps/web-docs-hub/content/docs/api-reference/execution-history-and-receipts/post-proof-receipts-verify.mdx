# POST /proof/receipts/verify

Compares submitted receipt values against the stored record for a known execution and returns the current proof status. The current handler compares stored values; it does not perform full cryptographic signature verification by itself.

## When To Use

Use this endpoint when the operation belongs to the Execution, History, and Receipts surface on the hosted API. It is intended to be the customer-facing contract for this capability.

## Integration Guidance

Do not blindly retry write operations. Retry only on transient 5xx or 429 responses, and make sure the client is idempotent or otherwise safe to replay.

### Common Mistakes

- Using the wrong credential type or forgetting to send the expected API key header.
- Replaying a write request without thinking through idempotency, duplication, or partial success.

## Request Body

| Field | Type | Required | Description |
|---|---|---|---|
| `execution_id` | `string` | Yes | Execution identifier to verify. |
| `expected_hash` | `string` | No | Compatibility alias for the comparison hash accepted by the current handler. |
| `hash` | `string` | Yes | Receipt hash value to compare against the stored record. |
| `signature` | `string` | Yes | Receipt signature value to compare against the stored record. |
