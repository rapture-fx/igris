# MCP Integration Patterns

This guide shows how to use the [MCP server](/docs/mcp-server) as part of a production
integration. MCP in Igris is an action/run control surface — these patterns are about
calling registered actions safely and inspecting what happened, not about storing
shared state.

---

## Pattern: Call Registered Actions, Not Inline Graphs

`call_action` runs an action you have already registered. The action definition owns
the target, policy, and approval behavior; the agent only supplies `input`.

Do this when you want agents to act through a reviewed, named contract rather than
constructing raw execution details at call time. The strict schema enforces this — the
agent supplies inputs to a registered action and cannot inject execution internals
through MCP.

## Pattern: Make Every Call Idempotent

Pass an `idempotency_key` on `call_action`. Idempotency is tenant-scoped: a repeated
key from the same tenant returns the existing run instead of starting a second one.

Choose a key that is stable for the logical operation (for example, a ticket ID or a
date-stamped job name), so an agent retry after a timeout does not double-run the
action.

## Pattern: Acknowledge, Then Inspect

`call_action` returns a `run_id` and an `inspect_ref` — it acknowledges acceptance,
not completion. Confirm the outcome with `get_run`, and pull audit metadata with
`get_run_evidence`. Do not treat the acknowledgement as proof the work finished.

## Pattern: Separate Working Context From Audit Data

Keep transient prompt/working state in your own application. Use `get_run_evidence`
and [receipts](/docs/execution-receipts) when you need the durable audit record.
Evidence records carry safe metadata, not raw request or response bodies — do not
expect MCP to hand back full payloads.

## Pattern: Confirm a Runtime Before Local Actions

If an action targets a local runtime, `call_action` is refused unless the tenant has a
healthy, reachable runtime connected. Use `list_runtimes` to confirm one is present and
routable before driving local-runtime actions from an agent. See
[Deploy Local Runtime](/docs/deploy-local-runtime) for the reachability requirement.
