# Console User Guide

The console is the operator view for Igris.

Its main job is to help teams inspect and operate:

- execution events and run history
- signed records and receipt-oriented workflows
- execution environments
- account, policy, and billing surfaces

This page focuses on the practical operator reading of the console rather than trying to document every advanced feature as if it were equally central.

---

## Dashboard

The dashboard is the summary view.

Use it to get a quick answer to questions like:

- are execution runs active
- are violations or alert-worthy events increasing
- are registered environments still visible
- are we approaching an environment-capacity limit

Treat it as an operator snapshot, not as the source of truth for deep execution analysis.

## Execution Runs

The most important console surface for many teams is the run view.

Use it to inspect:

- current run status
- pause, cancellation, or review state
- run metadata
- links into receipt and follow-up workflows

This is the console surface that maps most directly to the Verify stage of the product model.

### Reviewing A Run That Needs Approval

When an agent runs a human-gated action, the run pauses in `approval_required` and waits
for a person to decide. The console run view is where an operator handles that decision.
The flow is:

1. Open the run that is waiting for approval.
2. Review the approval panel on the run.
3. Read the safe metadata shown for the decision: the approval reason, the required
   capability names, the policy preset, the action target type, and a request summary
   when one is available. This metadata is name-only and redacted. It does not show
   payloads, request bodies, headers, secrets, or the run input.
4. Approve the run to continue it. Approval dispatches the run for execution.
5. Reject the run to stop it. A rejected run is never dispatched. Add a short reason when
   the reject control offers one.
6. Review the updated run state. Approved runs move on to execution and proof; rejected
   runs are closed.

The same decision is available over the API. See [Approvals](/docs/approval-workflows)
for the request and response shapes and for how approval fits the controlled action path.

## Proof, Receipts, And Violations

The proof-oriented areas of the console help operators inspect:

- signed or receipt-oriented records
- policy-violation follow-up
- what should be verified before evidence leaves the product boundary

Use these views together with:

- [Verification](/docs/verification)
- [Execution Receipts](/docs/execution-receipts)
- [Receipts and Audit Workflow](/docs/receipts-audit-workflow)

## Execution Environments

The console also shows registered execution environments and their visibility state.

That is useful for:

- checking whether a runtime environment is registered
- confirming heartbeat visibility
- staging rollout work carefully

The console should not be read as proof that all environment-management automation is broadly ready across every workflow. Use [Proof Status](/docs/proof-status) when rollout or update claims matter.

## Policy And Governance Views

Console policy and governance views are operator tools for:

- checking whether boundaries are behaving as expected
- investigating violations
- reviewing the effect of permission and policy changes

They are useful because policy only matters if the run and its results can still be inspected afterward.

## Billing And Account Areas

The console also includes account and billing surfaces.

Use them when you need:

- tier visibility
- environment-capacity awareness
- account-key management
- upgrade or subscription actions

These views are commercial controls around the execution system, not part of the execution model itself.

## How To Read The Console

The shortest useful mental model is:

1. use the dashboard for snapshot awareness
2. use execution runs and history for inspection
3. use receipt and proof surfaces for evidence workflows
4. use environment views for runtime visibility and rollout checks
5. use billing and account views for commercial controls
