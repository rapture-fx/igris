# Model Aggregation

> **Infinite Tier** — Federated model aggregation is included with the Infinite plan.

Igris supports federated learning across your fleet of Runtime devices, enabling collaborative model improvement without sharing raw data between devices.

---

## What It Is

Model Aggregation (federated learning) allows multiple Runtime devices to train local model updates (LoRA adapters) and aggregate them into a global model improvement — all without sending training data off-device.

```
Device A: trains local adapter ──┐
Device B: trains local adapter ──┼──► Aggregator → Global model update
Device C: trains local adapter ──┘
```

Each device:
1. Trains a LoRA adapter on its local execution history
2. Sends only the adapter weights (encrypted) to the aggregator
3. Receives the aggregated global model update
4. Applies the update to its local model

Raw execution data never leaves the device.

## Aggregation Rounds

Federated learning operates in rounds:

1. **Round Start** — The coordinator triggers a new aggregation round
2. **Local Training** — Each participating device trains its LoRA adapter
3. **Weight Upload** — Devices upload encrypted adapter weights
4. **Aggregation** — The coordinator computes a weighted average of all adapters
5. **Distribution** — The aggregated model is sent back to all participants
6. **Application** — Each device loads the updated model

### Round Configuration

```json
{
  "federated_learning": {
    "enabled": true,
    "min_participants": 3,
    "round_interval_mins": 60,
    "max_rounds_per_day": 12,
    "privacy_budget": 1.0,
    "noise_scale": 0.1
  }
}
```

| Field | Type | Default | Description |
|---|---|---|---|
| `enabled` | bool | `false` | Enable federated learning |
| `min_participants` | int | 3 | Minimum devices required to start a round |
| `round_interval_mins` | int | 60 | Time between aggregation rounds |
| `max_rounds_per_day` | int | 12 | Maximum rounds per day |
| `privacy_budget` | float | 1.0 | Differential privacy budget (ε) |
| `noise_scale` | float | 0.1 | Noise added to weights for privacy |

---

## Privacy

Federated learning in Igris includes differential privacy guarantees:

- **Noise injection** — Gaussian noise is added to adapter weights before upload
- **Privacy budget** — The total privacy loss (ε) is tracked across rounds
- **Clipping** — Weight updates are clipped to a maximum norm before aggregation

The privacy budget ensures that no individual device's training data can be reconstructed from the aggregated model.

## API

### GET /v1/federated/status

Current status of the federated learning coordinator.

```bash
curl https://overture.igrisinertial.com/v1/federated/status \
  -H "Authorization: Bearer YOUR_API_KEY"
```

Response:
```json
{
  "enabled": true,
  "active_round": 12,
  "total_rounds": 47,
  "participants": 8,
  "last_aggregated": "2026-03-01T10:00:00Z",
  "privacy_budget": 1.0,
  "noise_scale": 0.1
}
```

### GET /v1/federated/participants

List active fleet participants (devices seen in the last 10 minutes).

### GET /v1/federated/rounds

List recent aggregation rounds.

```json
[
  {
    "id": 12,
    "started_at": "2026-03-01T11:30:00Z",
    "status": "running",
    "participant_count": 8,
    "updates_received": 5,
    "model_version": "v1.4"
  }
]
```

### POST /v1/federated/rounds/start

Manually trigger a new aggregation round.

### GET /v1/federated/config

Returns current federated learning configuration.

### PUT /v1/federated/config

Update federated learning configuration.
