# SLO Enforcer

Igris enforces Service Level Objectives (SLOs) at the routing layer to ensure every inference request meets your latency, cost, and quality targets.

---

## What It Does

The SLO Enforcer sits between incoming requests and the provider routing engine. It evaluates each request against your configured SLOs and:

- **Routes to providers** that historically meet your latency targets
- **Terminates slow requests** that exceed your maximum latency budget
- **Falls back** to faster (possibly cheaper) providers when the primary is degraded
- **Records SLO compliance** in every execution receipt

SLO enforcement is independent of the capability model — it governs *how well* the execution performs, not *what* it is allowed to do.

---

## SLO Configuration

SLOs are configured per-tenant and apply to all inference requests unless overridden per-request.

```json
{
  "slo": {
    "latency_p99_ms": 2000,
    "latency_p50_ms": 500,
    "max_cost_per_request_usd": 0.05,
    "min_quality_score": 0.85,
    "violation_action": "fallback"
  }
}
```

## Violation Actions

When an SLO is breached, the enforcer takes the configured action:

### `fallback`

Immediately route to the next-best provider in the fallback chain. If no provider can meet the SLO, the request is terminated with a 503.

### `terminate`

Kill the in-flight request and return an error response. The violation is recorded in the receipt.

### `log_only`

Allow the request to complete but record the SLO breach. Useful during SLO tuning or when you want visibility without enforcement.

---

## How Latency Enforcement Works

The enforcer tracks provider latency in real time using an exponential moving average (EMA):

```
EMA_new = α × latency_current + (1 - α) × EMA_previous
```

Where `α` is a configurable smoothing factor (default 0.3). Providers whose EMA exceeds your `latency_p99_ms` are deprioritized in routing decisions.

If a request's wall time exceeds `latency_p99_ms` during execution, the enforcer triggers the violation action.

---

## Cost Enforcement

The enforcer tracks per-request cost based on token usage and provider pricing. If a request would exceed `max_cost_per_request_usd`:

1. The engine estimates cost before sending to the provider (based on input tokens)
2. If the estimate exceeds the limit, the request is rejected before inference
3. If the actual cost exceeds the limit (due to output tokens), the violation is recorded

Cost enforcement is available on **Horizon** and **Infinite** tiers.

---

## Quality Enforcement

Quality SLOs use the routing advisor's statistical scoring to evaluate response quality. If a provider's recent quality score drops below `min_quality_score`:

1. The provider is deprioritized in routing
2. Council Mode is automatically enabled if available
3. Speculative Execution may be triggered to race against a backup provider

Quality enforcement requires the routing advisor to be enabled.

---

## SLO Dashboard

View SLO compliance in the Console at `/dashboard`:

- **Compliance rate** — percentage of requests meeting all SLOs in the last 24h
- **Latency histogram** — distribution of response times
- **Cost chart** — per-request cost over time with SLO threshold line
- **Top violations** — which SLOs are breached most frequently

## API

### GET /v1/slo/config

Returns your current SLO configuration.

```bash
curl https://overture.igrisinertial.com/v1/slo/config \
  -H "Authorization: Bearer YOUR_API_KEY"
```

### POST /v1/slo/config

Update SLO configuration.

```bash
curl -X POST https://overture.igrisinertial.com/v1/slo/config \
  -H "Authorization: Bearer YOUR_API_KEY" \
  -H "Content-Type: application/json" \
  -d '{
    "latency_p99_ms": 1500,
    "max_cost_per_request_usd": 0.03,
    "violation_action": "fallback"
  }'
```

### GET /v1/slo/compliance

Returns SLO compliance metrics for the selected time range.

```bash
curl "https://overture.igrisinertial.com/v1/slo/compliance?range=24h" \
  -H "Authorization: Bearer YOUR_API_KEY"
```

Response:
```json
{
  "compliance_rate": 0.973,
  "total_requests": 4821,
  "violations": {
    "latency": 87,
    "cost": 12,
    "quality": 0
  },
  "avg_latency_ms": 342,
  "p99_latency_ms": 1847
}
```
