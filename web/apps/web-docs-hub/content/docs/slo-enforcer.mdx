# SLO Enforcer

Igris uses SLO enforcement to keep routing and runtime execution inside operational bounds. The enforcer evaluates live metrics, classifies breaches, and produces remediation actions that the platform can execute or record.

The current customer-facing contract is not a standalone SLO configuration API. Customers see SLO outcomes through routing behavior, provider health, execution receipts, history, and observability views.

---

## What Is Enforced

The production enforcer evaluates these metric inputs:

| Metric | Target | Warning | Critical |
|---|---:|---:|---:|
| `p99_latency_ms` | `100` | `130` | `150` |
| `p95_latency_ms` | `50` | `80` | `100` |
| `error_rate` | `0.001` | `0.01` | `0.02` |
| `availability` | `0.9999` | `0.999` | `0.99` |
| `throughput_rps` | `10000` | `8000` | `5000` |

The enforcer is configured with a 20-second evaluation interval and a 300-second breach cooldown. Auto-remediation is enabled in the default production configuration.

---

## Evaluation Output

SLO evaluations are exposed to customers through supported product surfaces rather than a standalone public SLO API. Use provider-health state, routing statistics, execution receipts, history, and observability exports to understand when the platform detected degraded behavior and how traffic was handled.

---

## Operational Access

SLO administration is not part of the public API reference. For enterprise deployments that require direct operational access, use the account-specific surfaces and runbooks provided with that deployment.

---

## Integration Guidance

Do not build customer automation against standalone SLO configuration or compliance routes; they are not part of the current production API.

For customer integrations:

- Use routing and provider-health APIs to observe whether the platform is routing around degraded providers.
- Use receipts and history for audit evidence.
- Use deployment monitoring for SLO dashboards.
- Treat remediation as platform behavior unless your deployment has explicitly exposed an admin SLO surface.
