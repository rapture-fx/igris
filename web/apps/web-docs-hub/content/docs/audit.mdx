# Audit

Audit in Igris starts from signed records and verification-ready receipts.

This page explains what operators can inspect after a run, how receipt data is queried and exported, and where verification semantics are stronger or weaker today.

---

## Primary Audit Artifact

The primary audit artifact is the execution receipt.

A receipt can include:

- request and run identity
- execution metadata
- status and timing
- capability or policy outcomes
- tool activity where applicable
- signed or hash-linked record material

Use [Execution Receipts](/docs/execution-receipts) for the receipt-oriented explanation and [Verification](/docs/verification) for the verification model.

---

## Lineage

Igris keeps lineage between request submission, execution activity, and post-run inspection surfaces.

That lets operators answer questions such as:

- which request created this run
- which execution path was taken
- what events were emitted
- which receipt corresponds to the final outcome

---

## Query And Export

Hosted audit surfaces can expose receipt listings, receipt retrieval, export workflows, and violation review. Use them to retain evidence outside the runtime when your retention or audit requirements demand it.

Typical workflows are:

1. list recent receipts
2. retrieve a specific run record
3. export receipts for external audit or retention
4. inspect recorded violations or review events

---

## Verification Semantics

Two verification paths matter here:

- the local proof-backed path, where signed record and receipt verification are demonstrated
- the hosted proof route, which confirms stored receipt values and proof status for a run

Use the hosted proof route for hosted receipt review workflows, and use the local proof-backed path when you need the stronger demonstrated cryptographic verification story.

---

## Retention

Receipt and audit retention depends on the environment and plan you operate with.

For stronger retention requirements:

- export hosted records before retention windows expire
- keep your own storage for local-only deployments
- treat receipts and tracing as complementary, not interchangeable
