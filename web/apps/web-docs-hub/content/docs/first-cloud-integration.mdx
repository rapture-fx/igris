# First Cloud Integration

Use this workflow when you want the shortest path from zero to a working Igris integration.

If your goal is to get a production integration live quickly, this is the path to follow. It keeps the contract simple, avoids deployment complexity, and lets you confirm the product value before you adopt deeper product surfaces.

The recommended sequence is:

1. Create a tenant API key
2. Add at least one provider key
3. Call the OpenAI-compatible API
4. Move to a native SDK only when you need Igris-specific features

---

## 1. Create a tenant API key

Create one tenant API key for the environment that will call the hosted API. Treat it like any other production secret and keep it in your standard secret store.

- [Trial & Billing →](/docs/trial-billing)
- [API Authentication →](/docs/api-reference/authentication)

## 2. Add a provider key

Igris routes requests using provider credentials stored in the vault. For most customer traffic today, use `openai` or `anthropic`.

```bash
curl -X POST https://overture.igrisinertial.com/v1/vault/keys \
  -H "Authorization: Bearer YOUR_IGRIS_API_KEY" \
  -H "Content-Type: application/json" \
  -d '{
    "provider": "openai",
    "key_name": "production",
    "api_key": "YOUR_OPENAI_KEY"
  }'
```

## 3. Call the OpenAI-compatible API

This should be your default starting point unless you already know you need native SDK features or local execution.

```typescript
import OpenAI from 'openai';

const client = new OpenAI({
  baseURL: 'https://overture.igrisinertial.com/v1',
  apiKey: process.env.IGRIS_API_KEY,
});

const response = await client.chat.completions.create({
  model: 'gpt-4o-mini',
  messages: [{ role: 'user', content: 'Summarize the latest fleet health' }],
});

console.log(response.choices[0].message.content);
```

## 4. Decide whether you need a native SDK

Stay on the OpenAI-compatible path if you need inference, broad language portability, and the least integration overhead.

Move to a native SDK when you need:

- receipt helpers
- vault operations
- fleet APIs
- richer routing metadata

The first-class native SDKs today are JavaScript/TypeScript, Go, and Rust.

- [SDKs →](/docs/sdk)
- [API Reference →](/docs/api-reference)

## Common Mistakes

- Starting with a preview SDK or a local runtime before proving that the hosted path already solves the use case
- Forgetting to add a provider key before sending hosted inference traffic
- Using a browser session flow for backend automation
