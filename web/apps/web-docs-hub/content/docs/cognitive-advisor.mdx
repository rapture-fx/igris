# Routing Advisor

The Routing Advisor analyzes your routing history and proposes configuration changes — adjusting provider weights, enabling speculative execution, or switching routing strategy — based on observed performance. Auto-apply can be configured to apply proposals automatically when they meet your confidence and risk thresholds.

---

## How It Works

1. The advisor monitors routing telemetry continuously
2. When it detects an optimization opportunity, it generates a **proposal** with a confidence score and a risk score
3. You can review and apply proposals manually, or configure auto-apply thresholds
4. Applied changes take effect immediately; a rollback window is available

---

## Proposals

### GET /v1/cognitive/proposals

List pending and recent proposals.

```bash
curl https://overture.igrisinertial.com/v1/cognitive/proposals \
  -H "Authorization: Bearer YOUR_API_KEY"
```

Response:
```json
[
  {
    "id": "prop-01HXYZ",
    "type": "routing_strategy",
    "description": "Switch to latency-optimized routing — Anthropic p50 has dropped 18% over 24h",
    "confidence": 0.91,
    "risk_score": 0.12,
    "estimated_improvement": "~18% latency reduction",
    "proposed_at": "2026-03-01T12:00:00Z",
    "status": "pending"
  }
]
```

| Field | Description |
|---|---|
| `confidence` | 0–1 — how certain the advisor is this change helps |
| `risk_score` | 0–1 — estimated risk of degradation |
| `status` | `pending`, `applied`, `rejected`, `rolled_back` |

---

### GET /v1/cognitive/proposals/:id

Get a single proposal with full detail.

---

### POST /v1/cognitive/proposals/:id/apply

Apply a proposal immediately.

```bash
curl -X POST https://overture.igrisinertial.com/v1/cognitive/proposals/prop-01HXYZ/apply \
  -H "Authorization: Bearer YOUR_API_KEY"
# → {"status": "applied", "applied_at": "2026-03-01T12:05:00Z"}
```

The change takes effect on the next request. If performance degrades within the rollback window, you can revert via the console or by applying the previous configuration manually.

## Auto-Apply Configuration

The advisor can apply proposals automatically when they meet configured thresholds. Set `enabled: true` in the auto-apply config to activate.

### GET /v1/cognitive/config

Returns the current auto-apply configuration.

```bash
curl https://overture.igrisinertial.com/v1/cognitive/config \
  -H "Authorization: Bearer YOUR_API_KEY"
```

Response:
```json
{
  "enabled": false,
  "confidence_threshold": 0.85,
  "max_risk_score": 0.25,
  "eval_interval_mins": 60,
  "rollback_window_mins": 30,
  "degradation_thresholds": {
    "latency_increase_pct": 10,
    "error_rate_increase_pct": 5,
    "cost_increase_pct": 15
  }
}
```

### PUT /v1/cognitive/config

Update the auto-apply configuration.

```bash
curl -X PUT https://overture.igrisinertial.com/v1/cognitive/config \
  -H "Authorization: Bearer YOUR_API_KEY" \
  -H "Content-Type: application/json" \
  -d '{
    "enabled": true,
    "confidence_threshold": 0.90,
    "max_risk_score": 0.20,
    "eval_interval_mins": 30,
    "rollback_window_mins": 15,
    "degradation_thresholds": {
      "latency_increase_pct": 10,
      "error_rate_increase_pct": 5,
      "cost_increase_pct": 15
    }
  }'
```

**Fields:**

| Field | Description |
|---|---|
| `enabled` | Enable auto-apply |
| `confidence_threshold` | Minimum confidence score for auto-apply (0–1) |
| `max_risk_score` | Maximum allowed risk score (0–1) |
| `eval_interval_mins` | How often to evaluate proposals |
| `rollback_window_mins` | How long to monitor after applying before confirming success |
| `degradation_thresholds` | Auto-rollback triggers: latency, error rate, cost increases |
