# Pricing & Tiers

Pricing is organized around the practical things teams buy from Igris:

- execution-environment capacity
- retention for signed records and run history
- operator surfaces and team workflows
- deployment flexibility

The commercial story should stay aligned with the product story: governed execution, verification-ready records, and deployment choice. It should not depend on presenting every advanced surface as broadly ready by default.

## What Tiers Primarily Differentiate

Tiers are best understood through operational differences:

- how many projects and execution environments you can run
- how many verified runs are included each month
- how long you retain run history and signed records
- whether you need deeper operator workflows and team access
- whether you need private deployment options

## Seed

Seed is the smallest paid footprint for teams that want to start running governed, verifiable AI tasks.

Good fit:

- early production teams
- one project and one execution environment
- teams with up to 2,500 verified runs per month
- short retention needs
- teams proving the value of signed records and governed execution first

## Horizon

Horizon is for teams that need broader operator visibility and more registered execution environments.

Good fit:

- teams running up to 5 projects and 10 execution environments
- teams that need 50,000 verified runs per month
- longer retention windows and event search
- teams that need day-to-day operator coordination, tool controls, and team access

## Infinite

Infinite is for organizations that need larger deployment scope and private deployment flexibility.

Good fit:

- custom execution-environment footprints and custom run volume
- private or self-managed deployment needs
- custom retention, audit export, onboarding, and security review needs

## What This Page Does Not Assume

This page intentionally does not sell unproven advanced surfaces as default tier promises.

Use careful language for:

- robotics and ROS2
- multimodal
- OTA-style rollout behavior
- broad fleet failover
- checkpoint recovery

Those areas should follow [Proof Status](/docs/proof-status) rather than being treated as blanket paid-tier guarantees.
