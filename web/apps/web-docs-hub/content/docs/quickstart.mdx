# Quick Start

Start here if you want to understand what Igris shows on first run and what the
advanced proof path verifies today.

This quickstart is intentionally not a generic hosted-inference tutorial. Direct model calls are fine for simple chat. Igris is for the point where AI output starts doing work and you need governed execution, visible failure paths, and records you can inspect after the run.

If you need the shortest hosted setup path after this proof-first walkthrough, Igris also supports an OpenAI-compatible onboarding path through the hosted API.

---

## What You Will Do First

Install the CLI and run the self-contained first-run demo:

```bash
curl -fsSL https://igrisinertial.com/install | bash
igris demo --recover-prove
```

This first-run path does not require Postgres, Docker, Homebrew Postgres, or a
repo checkout. It prints a local execution story URL and labels the result as
demo evidence, not a production deployment.

The output shows:

- action requested
- policy applied
- runtime boundary recorded
- task executed
- irreversible replay blocked
- receipt verification status

## Advanced Local Validation

Use this path when you are contributing to Igris or validating the full local
proof loop from source.

1. Start a local proof-backed Igris flow.
2. Send one request through the public execution surface.
3. Confirm that execution was routed through Runtime.
4. Verify the signed execution envelope, signed execution receipt, and receipt-log chain.

This advanced path is the narrowest contributor validation path that is proven
locally today.

## Prerequisites

- A checkout of this repository
- `node`, `go`, `cargo`, `curl`, and `lsof`
- Free local ports `8080` and `8081`
- Free local port `18090` if you run the default mock-provider mode

You do not need sanctioned provider credentials for the default proof path. The default mode uses a local mock upstream so the proof stays reproducible.

## 1. Run The First Verified Flow

From the repo root:

```bash
./scripts/unified_execution_proof_demo.sh
```

The script prepares local proof artifacts, builds or reuses the Runtime binary, builds Overture, starts a local mock upstream, starts Runtime on `127.0.0.1:8080`, starts Overture on `127.0.0.1:8081`, submits one `/v1/infer` request, and fails if Overture falls back away from Runtime.

Expected output shape:

```text
Unified execution proof succeeded.
Mode: mock
Provider: local-mock-cloud
Route decision: forwarded_to_runtime_task
Receipt execution_id: ...
Receipt hash: ...
Artifacts: /tmp/igris-unified-proof.XXXXXX
```

## 2. Inspect What Was Verified

The proof demonstrates the Request -> Execute -> Verify path:

- **Request**: the script sends one request through Overture's `/v1/infer` surface.
- **Execute**: Overture forwards the work to Runtime instead of silently answering from its own direct fallback path.
- **Verify**: the script checks the returned `execution_envelope`, `execution_receipt`, receipt hash, and receipt-log chain.

If the script succeeds, you have a local proof that:

- Runtime handled the execution authority for the request
- execution metadata captured the route decision
- the signed execution envelope verified
- the signed execution receipt verified
- the receipt hash matched the recomputed digest
- the receipt was present in the local receipt log with a valid chain link

## 3. Know What This Does And Does Not Prove

| Claim | Current status |
|---|---|
| Unified local Request -> Execute -> Verify flow | Proven locally |
| Signed records and receipt-chain verification on the local proof path | Proven locally |
| Capability-gated task execution | Proven locally in the proof artifacts and audits |
| Real provider-backed Runtime execution | Wired and configurable, but not proven in the prior environment |
| Local GGUF fallback | Source-confirmed, not proven in this quickstart |
| Checkpoint recovery | Source-confirmed, not proven in this quickstart |
| Fleet failover, OTA/config push, ROS2, multimodal | Advanced or preview areas, not part of this quickstart |

## 4. Real Provider Mode Is Deliberately Separate

The proof demo also supports a real-provider mode, but it should only be used with sanctioned credentials and it was not proven in the prior environment.

Example shape:

```bash
export IGRIS_UNIFIED_PROVIDER_MODE=real
export IGRIS_REAL_PROVIDER=openai
export OPENAI_API_KEY=...
./scripts/unified_execution_proof_demo.sh
```

Use this only when you are intentionally proving a sanctioned provider path. Do not treat it as part of the default onboarding path.
