# Fleet Management

Fleet management in the current product is the control-plane contract for runtime registration, heartbeat, queued commands, config push, and OTA updates.

---

## Registration

The stock runtime attempts registration automatically when both `IGRIS_LICENSE_KEY` and `IGRIS_API_KEY` are present at startup. If you need to integrate a custom launcher, use the current registration contract:

```bash
curl -X POST https://overture.igrisinertial.com/api/v1/runtime/register \
  -H "X-API-Key: YOUR_API_KEY" \
  -H "Content-Type: application/json" \
  -d '{
    "machine_id": "edge-gateway-01",
    "hostname": "edge-gateway-01",
    "platform": "linux-amd64",
    "runtime_version": "1.6.0",
    "endpoint": "http://192.168.1.100:8080"
  }'
```

Current response shape:

```json
{
  "runtime_id": "runtime-01HXYZ",
  "tier": "horizon",
  "runtime_limit": 50,
  "registered_at": "2026-03-01T12:00:00Z"
}
```

## Heartbeats And Commands

Runtime coordination routes:

- `POST /api/v1/runtime/heartbeat`
- `DELETE /api/v1/runtime/deregister`
- `GET /api/v1/runtime/commands`

Use these as runtime-to-control-plane endpoints rather than customer UI endpoints.

## Listing Registered Runtimes

Use the current fleet listing route:

```bash
curl "https://overture.igrisinertial.com/api/v1/runtime/list?tenant_id=YOUR_TENANT_ID" \
  -H "Authorization: Bearer YOUR_API_KEY"
```

Current response shape:

```json
{
  "runtimes": [
    {
      "runtime_id": "runtime-01HXYZ",
      "tenant_id": "tenant-123",
      "registered_at": 1711900800,
      "last_heartbeat": 1711900860,
      "stats": {}
    }
  ],
  "count": 1
}
```

When a tenant-authenticated console context exists, the tenant ID can be derived from auth instead of a query parameter.

## Configuration Push

### POST /api/v1/runtime/config/push

```bash
curl -X POST https://overture.igrisinertial.com/api/v1/runtime/config/push \
  -H "Authorization: Bearer YOUR_API_KEY" \
  -H "Content-Type: application/json" \
  -d '{
    "selector": {"tags": ["site-a"]},
    "config": {
      "local_fallback": {
        "enabled": true,
        "model_path": "/models/phi-3-mini-q4.gguf"
      }
    }
  }'
```

This queues a `config_push` command into runtime pending-command state.

---

## OTA Updates

### POST /api/v1/runtime/update

```bash
curl -X POST https://overture.igrisinertial.com/api/v1/runtime/update \
  -H "Authorization: Bearer YOUR_API_KEY" \
  -H "Content-Type: application/json" \
  -d '{
    "version": "runtime-v1.6.0",
    "strategy": "rolling",
    "max_unavailable": 1
  }'
```

The current API accepts:

- `version`
- `strategy`
- `max_unavailable`
- optional `selector`
