# Model Aggregation (Technical Preview)

Model aggregation is a specialized, preview-oriented surface in Igris.

It is not part of the default Request -> Execute -> Verify path, and it should not be treated as a proof-backed production capability today.

See [Proof Status](/docs/proof-status) before planning around this page.

---

## What This Page Covers

In the codebase, Igris includes source-confirmed structures for federated-style learning workflows where multiple configured execution environments contribute updates to a shared model-improvement process.

The high-level idea is:

1. local environments produce model-adaptation artifacts
2. those artifacts are collected centrally
3. an aggregated result is redistributed

That is useful for organizations exploring privacy-preserving adaptation workflows, but the public proof for this area is still limited.

---

## What Is Confirmed Today

- source-confirmed configuration and API surfaces exist for model-aggregation-style workflows
- the idea fits naturally with hosted and hybrid deployment modes
- operators can reason about this as a specialized execution-environment workflow rather than a separate product

---

## What Is Not Proven Here

- end-to-end production model aggregation across real customer environments
- public proof for privacy guarantees or convergence behavior
- rollout guidance strong enough to treat this as generally available

For those reasons, this page should be read as technical preview guidance, not a deployment commitment.

---

## When To Evaluate It

Evaluate model aggregation only if you already need:

- local adaptation close to where work happens
- coordination across multiple configured execution environments
- stronger control over what data leaves the execution surface

If your immediate goal is governed execution with signed records and verification-ready receipts, start with the standard docs path instead.
