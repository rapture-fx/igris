# Provider Health

Provider health is an advanced hosted coordination mechanism inside the **Execute** stage.

Its purpose is straightforward: help Igris avoid obviously unhealthy upstream paths and make failure-aware execution decisions. This page is about the mechanics of that decision support, not about turning routing into the product identity.

---

## What Provider Health Means

Provider health asks whether a configured upstream path appears usable right now.

Typical signals include:

- response success or failure
- latency behavior
- recent throughput
- health-check outcomes where those are enabled

These signals help path selection, but they do not guarantee a perfect execution outcome.

## Health States

The exact thresholds depend on configuration, but the common states are:

- **active** when the path looks healthy enough to use normally
- **degraded** when the path is still available but should be treated more cautiously
- **unavailable** when the path should not receive ordinary execution traffic

This is about failure visibility and safer path selection, not a blanket survival promise.

## Why It Matters

Provider health helps operators answer:

- which upstream paths are currently usable
- whether a sudden latency or error spike should reduce traffic
- whether a path should be removed from ordinary selection until it recovers

That makes it part of governed execution rather than just a dashboard nicety.

## How It Affects Execution

Provider health feeds into hosted path selection alongside:

- policy
- trust
- circuit-breaker state
- any advanced routing mode in use

Health should narrow the set of usable paths before an advanced routing strategy makes its final choice.

## Monitoring Surfaces

Use the health APIs and console views to inspect health state, but keep expectations realistic:

- health telemetry helps explain execution behavior
- health telemetry does not by itself prove performance or reliability outcomes for every workload

## Proof Language

Provider health is an advanced execution mechanism with real implementation support. It is appropriate to describe it as failure-aware path selection, but not as a guarantee that every outage or degradation scenario is already solved automatically.
