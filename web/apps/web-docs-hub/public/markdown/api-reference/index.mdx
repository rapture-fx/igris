# API Reference

This is the customer-facing API contract for Igris. Use the guide pages first, then move into the grouped endpoint reference when you are implementing or debugging a specific route.

## Start Here

- [Introduction](/docs/api-reference/introduction) — How the Igris API reference is organized, when to use each access point, and how to move from guides into endpoint-level integration work.
- [Authentication](/docs/api-reference/authentication) — Which credentials belong to automation, browser sessions, and runtime-local deployments, and how to choose the right one for each route.
- [Errors](/docs/api-reference/errors) — How to read error responses across the API reference and what to expect from validation, authentication, throttling, and server failures.
- [Rate Limits](/docs/api-reference/rate-limits) — What throttling exists today, where it applies, and how clients should behave when they receive a 429 response.

## Inference & Integration

Supported cloud inference endpoints. `/v1/chat/completions` is OpenAI-compatible, while `/v1/infer` exposes the native Igris request contract.

- [`POST /v1/infer`](/docs/api-reference/inference-integration/post-v1-infer) — Native inference endpoint handled by Overture.
- [`POST /v1/chat/completions`](/docs/api-reference/inference-integration/post-v1-chat-completions) — OpenAI-compatible chat completions endpoint.
- [`GET /v1/health`](/docs/api-reference/inference-integration/get-v1-health) — Health check for inference availability.
- [`GET /v1/models`](/docs/api-reference/inference-integration/get-v1-models) — Lists models visible to the inference layer.
- [`GET /v1/providers/stats`](/docs/api-reference/inference-integration/get-v1-providers-stats) — Provider latency, health, and routing statistics.
- [`POST /v1/infer/multimodal`](/docs/api-reference/inference-integration/post-v1-infer-multimodal) — Multimodal inference endpoint.
- [`GET /v1/infer/multimodal/stats`](/docs/api-reference/inference-integration/get-v1-infer-multimodal-stats) — Multimodal request statistics.

## Runtime Distribution & Fleet Coordination

Supported endpoints for downloading `igris-runtime`, registering runtime instances, and managing fleet operations from the control plane.

- [`GET /v1/runtime/install`](/docs/api-reference/runtime-distribution-fleet-coordination/get-v1-runtime-install) — Returns or redirects to the platform-specific runtime archive.
- [`GET /v1/runtime/checksum`](/docs/api-reference/runtime-distribution-fleet-coordination/get-v1-runtime-checksum) — Returns the SHA-256 checksum for a runtime archive.
- [`GET /v1/runtime/download`](/docs/api-reference/runtime-distribution-fleet-coordination/get-v1-runtime-download) — Subscribed runtime binary download endpoint.
- [`GET /api/v1/runtime/download`](/docs/api-reference/runtime-distribution-fleet-coordination/get-api-v1-runtime-download) — API-key authenticated runtime binary download endpoint for runtime installers.
- [`POST /api/v1/runtime/register`](/docs/api-reference/runtime-distribution-fleet-coordination/post-api-v1-runtime-register) — Registers a runtime instance with the hosted control plane.
- [`POST /api/v1/runtime/heartbeat`](/docs/api-reference/runtime-distribution-fleet-coordination/post-api-v1-runtime-heartbeat) — Refreshes runtime liveness and reports whether commands are pending.
- [`GET /api/v1/runtime/commands`](/docs/api-reference/runtime-distribution-fleet-coordination/get-api-v1-runtime-commands) — Fetches and clears queued commands for a registered runtime.
- [`DELETE /api/v1/runtime/deregister`](/docs/api-reference/runtime-distribution-fleet-coordination/delete-api-v1-runtime-deregister) — Marks a runtime instance as deregistered.
- [`GET /api/v1/runtime/list`](/docs/api-reference/runtime-distribution-fleet-coordination/get-api-v1-runtime-list) — Lists registered runtime instances for a tenant.
- [`POST /api/v1/runtime/config/push`](/docs/api-reference/runtime-distribution-fleet-coordination/post-api-v1-runtime-config-push) — Queues configuration push commands for the fleet.
- [`POST /api/v1/runtime/update`](/docs/api-reference/runtime-distribution-fleet-coordination/post-api-v1-runtime-update) — Queues OTA update commands for the fleet.

## Account, Trial, and Billing

Supported account and billing endpoints for subscription state and tenant API key lifecycle management.

- [`GET /api/subscription/status`](/docs/api-reference/account-trial-and-billing/get-api-subscription-status) — Returns subscription tier, status, and runtime usage.
- [`GET /api/subscription/plans`](/docs/api-reference/account-trial-and-billing/get-api-subscription-plans) — Lists available plans and checkout URLs.
- [`GET /v1/account/api-key`](/docs/api-reference/account-trial-and-billing/get-v1-account-api-key) — Returns current API key metadata without revealing the secret.
- [`POST /v1/account/api-key`](/docs/api-reference/account-trial-and-billing/post-v1-account-api-key) — Creates a new tenant API key and revokes the old one.
- [`DELETE /v1/account/api-key`](/docs/api-reference/account-trial-and-billing/delete-v1-account-api-key) — Revokes the current tenant API key.

## Vault, Policy, and Governance

Supported BYOK and tenant policy routes.

- [`GET /v1/vault/keys`](/docs/api-reference/vault-policy-and-governance/get-v1-vault-keys) — Lists configured provider keys with masked values.
- [`POST /v1/vault/keys`](/docs/api-reference/vault-policy-and-governance/post-v1-vault-keys) — Stores a provider key using `{ provider, key_name, api_key }`.
- [`GET /v1/vault/keys/:provider`](/docs/api-reference/vault-policy-and-governance/get-v1-vault-keys-provider) — Gets a single provider key record.
- [`DELETE /v1/vault/keys/:provider`](/docs/api-reference/vault-policy-and-governance/delete-v1-vault-keys-provider) — Deletes a provider key.
- [`POST /v1/vault/keys/:provider/rotate`](/docs/api-reference/vault-policy-and-governance/post-v1-vault-keys-provider-rotate) — Rotates a provider key.
- [`POST /v1/vault/keys/:provider/validate`](/docs/api-reference/vault-policy-and-governance/post-v1-vault-keys-provider-validate) — Validates a provider key with the current backend implementation.
- [`GET /v1/policy`](/docs/api-reference/vault-policy-and-governance/get-v1-policy) — Returns tenant policy document.
- [`PUT /v1/policy`](/docs/api-reference/vault-policy-and-governance/put-v1-policy) — Replaces tenant policy document.
- [`GET /v1/policy/history`](/docs/api-reference/vault-policy-and-governance/get-v1-policy-history) — Returns tenant policy history.

## Execution, History, and Receipts

Supported audit and receipt endpoints for customer-visible history and proof verification.

- [`GET /v1/history/events`](/docs/api-reference/execution-history-and-receipts/get-v1-history-events) — Lists execution history events. Supports `range`, `limit`, `agent_id`, and `device_id`.
- [`GET /v1/receipts`](/docs/api-reference/execution-history-and-receipts/get-v1-receipts) — Lists execution receipts from the coordination layer.
- [`GET /v1/receipts/:id`](/docs/api-reference/execution-history-and-receipts/get-v1-receipts-id) — Gets a single execution receipt by execution ID.
- [`GET /v1/receipts/export`](/docs/api-reference/execution-history-and-receipts/get-v1-receipts-export) — Exports receipts as JSONL or CSV.
- [`POST /proof/receipts/verify`](/docs/api-reference/execution-history-and-receipts/post-proof-receipts-verify) — Verifies a receipt signature and chain integrity.

## Routing Control & Analytics

Customer-visible routing controls and read models for adaptive routing, speculative execution, council mode, provider weighting, and circuit-breaker state.

- [`GET /v1/routing/stats`](/docs/api-reference/routing-control-analytics/get-v1-routing-stats) — Returns aggregate routing request and latency statistics.
- [`GET /v1/routing/recent`](/docs/api-reference/routing-control-analytics/get-v1-routing-recent) — Lists recent routed requests for operational inspection.
- [`GET /v1/routing/leaderboard`](/docs/api-reference/routing-control-analytics/get-v1-routing-leaderboard) — Ranks providers by recent routing performance.
- [`POST /v1/routing/strategy`](/docs/api-reference/routing-control-analytics/post-v1-routing-strategy) — Saves the tenant routing strategy configuration.
- [`POST /v1/routing/provider_weights`](/docs/api-reference/routing-control-analytics/post-v1-routing-provider-weights) — Saves tenant provider weight overrides.
- [`GET /v1/routing/speculative/status`](/docs/api-reference/routing-control-analytics/get-v1-routing-speculative-status) — Returns current speculative-routing status metrics.
- [`GET /v1/routing/speculative/config`](/docs/api-reference/routing-control-analytics/get-v1-routing-speculative-config) — Returns the active speculative-routing configuration read model.
- [`POST /v1/routing/speculative`](/docs/api-reference/routing-control-analytics/post-v1-routing-speculative) — Saves tenant speculative-routing configuration.
- [`GET /v1/routing/speculative/analytics`](/docs/api-reference/routing-control-analytics/get-v1-routing-speculative-analytics) — Returns speculative-routing analytics series.
- [`POST /v1/routing/speculative/simulate`](/docs/api-reference/routing-control-analytics/post-v1-routing-speculative-simulate) — Triggers a speculative-routing simulation for a sample request.
- [`POST /v1/routing/council`](/docs/api-reference/routing-control-analytics/post-v1-routing-council) — Saves tenant council-mode routing configuration.
- [`GET /v1/routing/council/analytics`](/docs/api-reference/routing-control-analytics/get-v1-routing-council-analytics) — Returns council-mode aggregate and per-chairman analytics.
- [`POST /v1/routing/shadow`](/docs/api-reference/routing-control-analytics/post-v1-routing-shadow) — Saves tenant shadow-routing configuration.
- [`GET /v1/routing/circuit-breaker/status`](/docs/api-reference/routing-control-analytics/get-v1-routing-circuit-breaker-status) — Returns aggregate and per-provider circuit-breaker state.

## Behavior Trees

Supported behavior-tree definition endpoints exposed by the coordination layer.

- [`GET /v1/bt/templates`](/docs/api-reference/behavior-trees/get-v1-bt-templates) — Lists built-in behavior-tree templates.
- [`GET /v1/bt/definitions`](/docs/api-reference/behavior-trees/get-v1-bt-definitions) — Lists tenant behavior-tree definitions.
- [`GET /v1/bt/definitions/:id`](/docs/api-reference/behavior-trees/get-v1-bt-definitions-id) — Gets a single behavior-tree definition.
- [`POST /v1/bt/definitions`](/docs/api-reference/behavior-trees/post-v1-bt-definitions) — Creates or upserts a behavior-tree definition.
- [`DELETE /v1/bt/definitions/:id`](/docs/api-reference/behavior-trees/delete-v1-bt-definitions-id) — Deletes a behavior-tree definition.

## Durable Tasks

Submit durable workflows and long-running tasks that preserve progress automatically across runtime interruptions.

- [`POST /v1/tasks/submit`](/docs/api-reference/durable-tasks/post-v1-tasks-submit) — Submit a durable task using `agent_workflow`, `robotics_workflow`, `single_inference`, or `behavior_tree`.
- [`GET /v1/tasks/:id`](/docs/api-reference/durable-tasks/get-v1-tasks-id) — Poll the current status and latest checkpoint metadata for a durable task.
- [`GET /v1/tasks`](/docs/api-reference/durable-tasks/get-v1-tasks) — List recent durable tasks for the authenticated tenant.
- [`GET /v1/tasks/:id/steps`](/docs/api-reference/durable-tasks/get-v1-tasks-id-steps) — Lists execution-graph steps and graph slots for a durable task when available.
- [`POST /v1/tasks/:id/cancel`](/docs/api-reference/durable-tasks/post-v1-tasks-id-cancel) — Requests cancellation for a non-terminal durable task.
- [`GET /v1/tasks/proof/readiness`](/docs/api-reference/durable-tasks/get-v1-tasks-proof-readiness) — Reports whether trigger-backed proof synchronization is active.
- [`POST /v1/tasks/:id/proof/verify`](/docs/api-reference/durable-tasks/post-v1-tasks-id-proof-verify) — Synchronizes and verifies persisted proof state for a durable task.

## MCP Transport

Hosted MCP transport routes for structured shared context and tool-oriented workflows.

- [`POST /v1/mcp`](/docs/api-reference/mcp-transport/post-v1-mcp) — Forwards JSON-RPC MCP requests to the configured runtime MCP server.
- [`POST /v1/mcp/stream`](/docs/api-reference/mcp-transport/post-v1-mcp-stream) — Forwards streaming MCP requests to the configured runtime MCP server.

- [`GET /v1/swarm/agents`](/docs/api-reference/local-runtime-api/get-v1-swarm-agents) — Lists local swarm agents.
