## Action Packs

Built-in Action Packs install safe registered actions for first-agent onboarding. A pack is a small manifest of action definitions — it does not execute raw tasks, call external providers, or store secrets. After install, run actions through the normal Actions API or MCP `call_action` like any other registered action.

- [`GET /v1/action-packs`](/docs/api-reference/action-packs/get-v1-action-packs) — Lists built-in Action Packs available for install into the authenticated tenant.
- [`POST /v1/action-packs/:name/install`](/docs/api-reference/action-packs/post-v1-action-packs-name-install) — Installs a built-in Action Pack by registering its actions in your tenant. Installed actions are normal registered actions — not raw task submissions.

## Agents

Tenant-scoped Agent Registry for identity and run attribution. Register an agent before first runs, then pass agent_id or agent_name on action runs and MCP call_action. Metadata is sanitized — no secrets, prompts, or tenant_id from clients.

- [`GET /v1/agents`](/docs/api-reference/agents/get-v1-agents) — Lists registered agents for the authenticated tenant. Use include_archived=true to include archived agents.
- [`POST /v1/agents`](/docs/api-reference/agents/post-v1-agents) — Registers a tenant-scoped agent identity for run attribution.
- [`GET /v1/agents/:id`](/docs/api-reference/agents/get-v1-agents-id) — Gets one registered agent by id.
- [`PATCH /v1/agents/:id`](/docs/api-reference/agents/patch-v1-agents-id) — Updates registry fields (name, display_name, description, agent_type, template_name, version, metadata) or execution settings (shadow_mode, reflection_mode, council_mode, cognitive_advisor_enabled) — not both in one request.
- [`DELETE /v1/agents/:id`](/docs/api-reference/agents/delete-v1-agents-id) — Archives a registered agent.

## Actions

Registered actions are the primary execution gateway. Define what work an agent is allowed to ask Igris to run, then run those actions through Igris with policy, tenant-scoped idempotency, runtime routing, recovery, and proof.

- [`GET /v1/actions`](/docs/api-reference/actions/get-v1-actions) — Lists the registered actions owned by the authenticated tenant.
- [`POST /v1/actions`](/docs/api-reference/actions/post-v1-actions) — Creates a registered action definition: the contract for what an agent may ask Igris to run.
- [`GET /v1/actions/:id`](/docs/api-reference/actions/get-v1-actions-id) — Gets one registered action definition by id.
- [`PATCH /v1/actions/:id`](/docs/api-reference/actions/patch-v1-actions-id) — Updates a registered action definition.
- [`DELETE /v1/actions/:id`](/docs/api-reference/actions/delete-v1-actions-id) — Archives a registered action so it can no longer be run.
- [`POST /v1/actions/run`](/docs/api-reference/actions/post-v1-actions-run) — Runs a registered action by id or name. Raw, unregistered action definitions are not accepted.
- [`POST /v1/actions/:name/run`](/docs/api-reference/actions/post-v1-actions-name-run) — Runs a registered action by name. This is the endpoint agents call in production.
- [`GET /v1/actions/runs/:id`](/docs/api-reference/actions/get-v1-actions-runs-id) — Inspects one action run: status, proof state, and a redacted input summary.

## Runtime Distribution & Fleet Coordination

Supported endpoints for downloading `igris-runtime`, registering runtime instances, and managing fleet operations from the control plane.

- [`GET /v1/runtime/install`](/docs/api-reference/runtime-distribution-fleet-coordination/get-v1-runtime-install) — Returns or redirects to the platform-specific runtime archive.
- [`GET /v1/runtime/checksum`](/docs/api-reference/runtime-distribution-fleet-coordination/get-v1-runtime-checksum) — Returns the SHA-256 checksum for a runtime archive.
- [`GET /v1/runtime/download`](/docs/api-reference/runtime-distribution-fleet-coordination/get-v1-runtime-download) — Subscribed runtime binary download endpoint.
- [`GET /api/v1/runtime/download`](/docs/api-reference/runtime-distribution-fleet-coordination/get-api-v1-runtime-download) — API-key authenticated runtime binary download endpoint for runtime installers.
- [`POST /api/v1/runtime/register`](/docs/api-reference/runtime-distribution-fleet-coordination/post-api-v1-runtime-register) — Registers a runtime instance with the hosted control plane.
- [`POST /api/v1/runtime/heartbeat`](/docs/api-reference/runtime-distribution-fleet-coordination/post-api-v1-runtime-heartbeat) — Refreshes runtime liveness and reports whether commands are pending.
- [`GET /api/v1/runtime/commands`](/docs/api-reference/runtime-distribution-fleet-coordination/get-api-v1-runtime-commands) — Fetches and clears queued commands for a registered runtime.
- [`DELETE /api/v1/runtime/deregister`](/docs/api-reference/runtime-distribution-fleet-coordination/delete-api-v1-runtime-deregister) — Marks a runtime instance as deregistered.
- [`POST /api/v1/runtime/config/push`](/docs/api-reference/runtime-distribution-fleet-coordination/post-api-v1-runtime-config-push) — Queues configuration push commands for the fleet. Experimental; disabled by default.
- [`POST /api/v1/runtime/update`](/docs/api-reference/runtime-distribution-fleet-coordination/post-api-v1-runtime-update) — Queues OTA update commands for the fleet. Experimental; disabled by default.

## Durable Tasks

Advanced durable-workflow endpoints for callers that need direct task definitions, long-running state, checkpoint metadata, and follow-up inspection. First-agent onboarding should use registered actions first.

- [`POST /v1/tasks/submit`](/docs/api-reference/durable-tasks/post-v1-tasks-submit) — Advanced API for submitting a durable task using `agent_workflow`, `robotics_workflow`, `single_inference`, or `behavior_tree`. Use registered actions for first-agent onboarding.
- [`GET /v1/tasks/:id`](/docs/api-reference/durable-tasks/get-v1-tasks-id) — Poll the current status and latest checkpoint metadata for a durable task.
- [`GET /v1/tasks`](/docs/api-reference/durable-tasks/get-v1-tasks) — List recent durable tasks for the authenticated tenant.
- [`GET /v1/tasks/:id/steps`](/docs/api-reference/durable-tasks/get-v1-tasks-id-steps) — Lists execution-graph steps and graph slots for a durable task when available.
- [`POST /v1/tasks/:id/cancel`](/docs/api-reference/durable-tasks/post-v1-tasks-id-cancel) — Requests cancellation for a non-terminal durable task.
- [`GET /v1/tasks/proof/readiness`](/docs/api-reference/durable-tasks/get-v1-tasks-proof-readiness) — Reports whether trigger-backed proof synchronization is active.
- [`POST /v1/tasks/:id/proof/verify`](/docs/api-reference/durable-tasks/post-v1-tasks-id-proof-verify) — Synchronizes and verifies persisted proof state for a durable task.

## MCP Transport

The agent-facing MCP endpoint. JSON-RPC `tools/list` and `tools/call` over a fixed, strict-schema tool set for registered actions, runs, evidence, and runtimes.

- [`POST /v1/mcp`](/docs/api-reference/mcp-transport/post-v1-mcp) — Agent-facing JSON-RPC MCP endpoint with strict tool schemas, scoped to the authenticated tenant.
