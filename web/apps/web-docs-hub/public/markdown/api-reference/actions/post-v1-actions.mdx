# POST /v1/actions

Creates a registered action definition. The definition declares the execution target, the HTTP method, and the policy that governs every run: preset, replay class, approval requirement, and irreversibility. Once registered, agents run the action by name — they never define execution payloads themselves.

## When To Use

Use this endpoint when setting up a new capability for your agents. Register the action once, then hand agents the action name and an API key. Action names are unique within your tenant.

## Integration Guidance

Creation is not idempotent by key, but a retried create with the same name fails safely with `409 action_name_conflict` rather than creating a duplicate.

### Common Mistakes

- Forgetting `target_url` for `hosted_api` or `webhook` actions — the action registers, but runs fail with `target_not_configured` until a target is set.
- Putting secret values in `secret_refs`. The field holds secret *names* only; values are configured on the execution target.
- Using an action name with uppercase letters or dashes. Names must match `^[a-z][a-z0-9_]{1,63}$`.

## Request Body

| Field | Type | Required | Description |
|---|---|---|---|
| `name` | `string` | Yes | Machine name for the action: lowercase letters, digits, and underscores (for example `send_invoice`). Unique within your tenant. |
| `display_name` | `string` | No | Human-readable name shown in the console. Defaults to `name`. |
| `description` | `string` | No | What this action does, for operators and agents. |
| `target_type` | `string` | No | Where the action runs: `hosted_api`, `webhook`, `local_runtime`, `hybrid_fallback`, or `mock_demo`. Defaults to `mock_demo`. |
| `target_url` | `string` | No | Target URL for `hosted_api` and `webhook` actions. Required before those actions can run. |
| `method` | `string` | No | HTTP method used against the target: GET, POST, PUT, PATCH, or DELETE. Defaults to POST. |
| `policy_preset` | `string` | No | Policy preset governing the action: `Safe automation`, `Human-gated`, `Non-replayable`, or `Read-only`. Defaults to `Safe automation`. |
| `replay_class` | `string` | No | Whether a run can be safely replayed during recovery, for example `retryable`. |
| `approval_required` | `boolean` | No | When true, every run pauses for human approval before executing. |
| `irreversible` | `boolean` | No | Marks the side effect as irreversible. Recovery will not automatically replay irreversible work. |
| `secret_refs` | `string[]` | No | Names of secrets the action target needs. References only — secret values are never sent or returned through this API. |
| `target_metadata` | `object` | No | Optional target settings. For `local_runtime` actions, `runtime_id` pins runs to one specific runtime. |

## Request Example

```json
{
  "name": "send_invoice",
  "display_name": "Send invoice",
  "description": "Send an invoice to a customer through the billing webhook.",
  "target_type": "webhook",
  "target_url": "https://billing.example.com/hooks/igris",
  "method": "POST",
  "policy_preset": "Safe automation"
}
```

## Status Codes

| Code | Title | Description |
|---|---|---|
| 201 | Created | The action definition was registered. |
| 400 | Invalid definition | The name, target type, method, or policy preset was not valid. |
| 401 | Unauthorized | Credentials were missing, expired, or not accepted. |
| 409 | Name conflict | An action with this name already exists in your tenant. |
