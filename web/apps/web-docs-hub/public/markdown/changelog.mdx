# Changelog

Release notes for Igris. Breaking changes are marked explicitly.

---

## docs — API contract and workflow documentation — April 2026

### Added

- Explicit API support labels (`Core`, `Supported`, `Preview`) and deployment modes (`Cloud`, `Local`, `Hybrid`) across the API reference
- Workflow documentation for first cloud integration, local runtime deployment, hybrid deployment, receipts and audit, and fleet rollout

### Changed

- Quick Start now presents the OpenAI-compatible API as the recommended onboarding path
- SDK guidance now states clearly that JavaScript/TypeScript, Go, and Rust are the current first-class native SDKs
- The public API reference no longer publishes runtime-to-control-plane callback routes as customer-facing endpoints

### Migration

No code migration is required. Recheck any bookmarked API pages or internal runbooks that depended on the removed runtime callback routes from the public reference.

---

## runtime-v1.8.0 — Stability & cgroup enforcement — March 2026

### Fixed

- **CPU quota enforcement** — resolved a bug that prevented CPU quota limits from being applied on Linux deployments; CPU-bounded execution now enforces limits as expected
- **cgroup period precision** — corrected an integer precision issue in cgroup period configuration that could cause silent truncation for long-period CPU quotas

### Changed

- **Safety containment** — cgroup bounds are now correctly enforced for all Linux deployments, preventing resource overconsumption by runaway executions

### Migration

No action required. Existing configurations continue to work. Deployments that previously had silent CPU quota truncation will now enforce limits correctly.

---

## runtime-v1.7.x — ARM64 support and distribution — March 2026

### Added

- **ARM64 support** — runtime binaries for `linux-arm64` are now built and published for all supported Linux ARM64 devices (Raspberry Pi 4/5, Jetson Orin)
- **Authenticated binary distribution** — runtime binaries are served through authenticated download endpoints with checksum verification

### Changed

- **Release pipeline** — all supported platforms (linux-amd64, linux-arm64, macos-arm64) are now built and published on each release
- **Installer** — install command updated to use `igrisinertial.com`; installer hardened with piped-stdin detection, checksum hard-fail, and API key prompt improvements

### Migration

- If you were using the old install script, update to the new URL
- macOS Intel users: continue using your current binary; no new builds will be published for Intel macOS

---

## runtime-v1.6.0 — macOS ARM64 builds — February 2026

### Changed

- **macOS builds** — Intel macOS build targets removed; only ARM64 (Apple Silicon) binaries are now published for macOS
- **Install command** — updated to use short domain across all documentation and install script references

### Migration

No action required for Linux deployments. macOS Intel users should continue using their current binary.

## v1.2.1-speculative — Speculative execution — November 2025

### Added

- **Speculative execution** — produces a **60% reduction in time-to-first-token (TTFT)** for streaming requests; enabled by default for all streaming inference
- **Production deployment** — speculative execution is live across all regions

### Changed

- **Default behavior** — speculative execution is now enabled by default for all streaming requests

---

## v0.4.0 — Runtime Hardening Phase 4 — October 2025

### Added

- **Agent namespace isolation** — each agent now executes in an isolated namespace; cross-agent resource access is denied by default
- **Capability enforcement model** — capability grants are declared in the execution envelope and enforced at runtime before any tool call proceeds
- **ExecutionReceipt (signed, hash-chained)** — every execution now produces a receipt that is cryptographically signed and chained to the previous receipt in the session, forming a tamper-evident log
- **Lifecycle state machine** — agents transition through formal states (`initializing → running → idle → degraded → terminated`); invalid transitions are rejected
- **Swarm message signing** — messages exchanged between swarm members are signed; unsigned or unverifiable messages are dropped
- **Transaction boundary** — tool sequences can be declared as a transaction; partial completion is recorded and surfaced in the receipt
- **Trust verification between cloud and edge** — the coordination layer and edge runtime now perform mutual trust verification on session establishment

### Changed

- **Breaking: Execution now requires verified envelope** — envelopes without a valid signature from an authorized issuer are rejected before any execution begins
- **Breaking: Runtime always emits signed receipt** — previously, receipt emission was conditional; it is now unconditional for every execution path including errors and timeouts

### Migration

- Ensure your SDK or integration sends properly signed execution envelopes
- Update any workflows that assumed conditional receipt emission

### Docs

- Unified documentation navigation across all product areas
- Governance model documentation — covers receipt chain, capability gates, and audit query API
- Execution receipt documentation — describes receipt structure, signing, chaining, and export
- Capability model documentation — covers grant declaration, enforcement, and override policy
