# Provider Trust

Provider trust is an advanced hosted coordination mechanism.

Health asks whether a path appears up right now. Trust asks whether that path should still be considered reliable enough to keep using for governed execution.

That distinction matters for advanced operators who want more than a binary up-or-down signal.

---

## What Trust Evaluates

Trust looks at observed behavior over time, such as:

- latency drift
- error-rate drift
- cost drift
- how much evidence exists for the path so far

This helps distinguish "technically available" from "credible enough to keep using."

## Why It Matters

A path can be healthy in the narrow sense and still be a poor choice if its behavior is drifting away from what operators expect.

Trust is the layer that says:

- this path is up, but not yet proven enough
- this path is up, but its behavior has drifted too far
- this path may need more evidence before it receives normal traffic

## Cold Start And Confidence

Trust grows with evidence.

New or rarely used paths may need a warm-up period before operators should treat them as ordinary choices for production execution. That is part of the point of having a separate trust concept.

## How It Affects Path Selection

Trust should sit ahead of final advanced routing decisions:

1. policy decides what is allowed
2. health decides what is currently usable
3. trust decides what is credible enough to keep using
4. final path selection chooses among the remaining candidates

## Proof Language

Provider trust is best described as an advanced, source-confirmed execution mechanism. It is appropriate to explain how it influences selection, but this page should not promise globally optimal or universally safer outcomes without deployment-specific evidence.
