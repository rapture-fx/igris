# Quick Start

Choose the simplest path that matches how you plan to run Igris.

If you are unsure where to begin, start with the hosted OpenAI-compatible API. It is the shortest path to a working production integration and the easiest path to validate product fit. Move to a native SDK when you need Igris-specific product features, and move to local runtime or hybrid deployment only when the workload truly needs on-device execution, fleet participation, or offline behavior.

---

## Prerequisites

- An Igris account at [console.igrisinertial.com](https://console.igrisinertial.com)
- One tenant API key (`igris_...`) from **Settings → API Keys**
- For cloud routing today, provider keys for the currently supported public vault identifiers: `openai` or `anthropic`
- For local runtime, a GGUF model file if you want on-device inference

---

## Option A: Cloud API

This is the recommended starting path for most customers. It gives you the fastest route from account setup to a live integration, while still keeping the door open to native SDKs and hybrid deployment later.

### 1. Add a provider key

The current public vault API accepts `openai`, `anthropic`, and the synthetic `benchmark` provider. For customer traffic, use `openai` or `anthropic`.

```bash
curl -X POST https://overture.igrisinertial.com/v1/vault/keys \
  -H "Authorization: Bearer YOUR_IGRIS_API_KEY" \
  -H "Content-Type: application/json" \
  -d '{
    "provider": "openai",
    "key_name": "production",
    "api_key": "YOUR_OPENAI_KEY"
  }'
```

### 2. Point your client at Igris

```typescript
import OpenAI from 'openai';

const client = new OpenAI({
  baseURL: 'https://overture.igrisinertial.com/v1',
  apiKey: process.env.IGRIS_API_KEY,
});

const response = await client.chat.completions.create({
  model: 'gpt-4o-mini',
  messages: [{ role: 'user', content: 'Hello' }],
});

console.log(response.choices[0].message.content);
```

That is enough for a production-grade first integration. Stay on this path if your main goal is hosted inference with the least amount of integration overhead. Move to a native SDK when you need receipt helpers, fleet APIs, vault operations, or richer routing metadata.

## Option B: Local Runtime

Use `igris-runtime` when the workload should execute on the machine itself: local inference, local policy enforcement, behavior-tree execution, or offline operation. If you do not need those properties, the hosted API is usually the better place to start.

### 1. Download the runtime archive

Pick your platform:

- `linux-amd64`
- `linux-arm64`
- `linux-armv7`
- `macos-arm64`
- `macos-x64`

Example:

```bash
export IGRIS_PLATFORM="linux-amd64"

curl -fL "https://overture.igrisinertial.com/v1/runtime/install?platform=${IGRIS_PLATFORM}" \
  -o /tmp/igris-runtime.tar.gz

curl -fL "https://overture.igrisinertial.com/v1/runtime/checksum?platform=${IGRIS_PLATFORM}"
```

The checksum endpoint returns the expected SHA-256 value for the archive. Verify it before installation using your platform checksum tool.

### 2. Extract and install

```bash
tar -xzf /tmp/igris-runtime.tar.gz -C /tmp
mkdir -p "$HOME/.local/bin"
mv /tmp/igris-runtime "$HOME/.local/bin/igris-runtime"
chmod +x "$HOME/.local/bin/igris-runtime"
export PATH="$HOME/.local/bin:$PATH"
```

### 3. Verify the binary

```bash
igris-runtime --version
```

### 4. Configure the runtime

Create `~/.config/igris/config.json5`:

```json5
{
  server: {
    host: "0.0.0.0",
    port: 8080
  },
  auth: {
    enabled: true,
    api_key: "YOUR_IGRIS_API_KEY"
  },
  local_fallback: {
    enabled: true,
    model_path: "/models/phi-3-mini-4k-instruct-q4.gguf",
    context_size: 4096,
    threads: 4,
    n_gpu_layers: 0
  }
}
```

### 5. Start the runtime

```bash
igris-runtime serve
```

At this point the runtime serves a local API on `http://localhost:8080`. That alone does **not** make the runtime part of Fleet. Fleet visibility only happens when runtime registration succeeds.

### 6. Point your application at the local runtime

```typescript
import OpenAI from 'openai';

const client = new OpenAI({
  baseURL: 'http://localhost:8080/v1',
  apiKey: process.env.IGRIS_API_KEY,
});

const response = await client.chat.completions.create({
  model: 'phi3',
  messages: [{ role: 'user', content: 'Hello' }],
});
```

## Option C: Hybrid Cloud + Local Runtime

Use this when you want the hosted product to remain the main application-facing API, but you also want runtimes to participate in fleet operations, failover, or device-local execution. This is the right model when the customer should experience one product while the execution topology spans cloud and runtime.

### 1. Start the runtime with registration credentials

`igris-runtime` only attempts fleet registration when both of these are present:

- `IGRIS_LICENSE_KEY`
- `IGRIS_API_KEY`

Example:

```bash
export IGRIS_LICENSE_KEY="YOUR_LICENSE_KEY"
export IGRIS_API_KEY="YOUR_IGRIS_API_KEY"
igris-runtime serve
```

If license validation succeeds and the control plane is reachable, the runtime will attempt registration on startup.

### 2. Use the cloud API from your application

Your app continues to call Overture:

```typescript
import OpenAI from 'openai';

const client = new OpenAI({
  baseURL: 'https://overture.igrisinertial.com/v1',
  apiKey: process.env.IGRIS_API_KEY,
});
```

Keep the runtime healthy and reachable if you expect it to participate in fleet workflows, device-local execution, or failover behavior.

## Troubleshooting

| Problem | What to check |
|---|---|
| `igris-runtime: command not found` | Ensure `$HOME/.local/bin` is on `PATH` or install to a directory already on `PATH`. |
| Local runtime does not answer | Check `http://localhost:8080/v1/health` after `igris-runtime serve`. |
| Fleet device never appears | Confirm `IGRIS_LICENSE_KEY` and `IGRIS_API_KEY` are both set before startup, and that the runtime can reach Overture. |
| Cloud routing returns auth errors | Verify you are using a current tenant API key with the `igris_` prefix. |
| Provider key creation fails | Use the currently supported provider identifiers in the public vault API: `openai` or `anthropic`. |
