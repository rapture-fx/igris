# Local LLM Fallback

`igris-runtime` can serve GGUF models locally and participate in hybrid deployments where cloud routing falls back to on-device inference.

---

## What Exists Today

The current runtime config surface is `local_fallback`. The shipped config supports local model loading and tuning knobs such as context size, threading, GPU layer offload, and prompt caching.

```json5
{
  local_fallback: {
    enabled: true,
    model_path: "/models/mistral-7b.Q4_K_M.gguf",
    context_size: 4096,
    threads: 4,
    n_gpu_layers: 0,
    max_tokens: 512,
    temperature: 0.7
  }
}
```

Optional fields also available in the current runtime:

- `main_gpu`
- `prompt_cache_dir`
- `batch_size`
- `lora_adapter_path`

---

## Configuration Fields

| Field | Description |
|---|---|
| `enabled` | Enables the local fallback subsystem |
| `model_path` | Path to the GGUF model on disk |
| `context_size` | Runtime context window size |
| `threads` | CPU threads for local inference |
| `n_gpu_layers` | Number of model layers offloaded to GPU |
| `max_tokens` | Default local generation cap |
| `temperature` | Default local sampling temperature |

There is no dedicated pure-local fallback toggle in the current runtime config. For pure local deployments, point clients directly at `http://localhost:8080/v1` and do not rely on cloud routing.

---

## Hybrid Behavior

In a hybrid deployment:

1. Your application calls Overture
2. Overture routes normally across cloud providers
3. If the runtime is registered and selected by your routing configuration, local execution can participate in the request path

In a fully local deployment:

1. Your application calls the runtime directly
2. The runtime answers from the local model
3. Signed execution receipts are returned with the response payload when enabled by the runtime path

---

## Supported Model Format

The current runtime expects GGUF model files on disk. Choose a model size that matches your hardware budget.

| Hardware | Suggested starting point |
|---|---|
| CPU-only edge box | Phi-3 Mini or other compact GGUF |
| Apple Silicon laptop | 7B to 8B GGUF models |
| Dedicated GPU host | Larger GGUF models with `n_gpu_layers` tuned upward |

---

## Operational Notes

- Local inference availability is controlled by the runtime process, not by a separate cloud toggle
- Console-side fleet visibility requires successful runtime registration; local inference itself does not
- When you call the runtime directly, runtime auth depends on your local `auth` config
