# Docs Authoring Components

These examples show the component patterns the docs should prefer going forward: native Fumadocs tabs, files, and structured tables instead of custom UI or ad hoc Markdown layouts.

## Tabs

<Tabs items={['Why', 'Pattern']}>
  <Tab value="Why">
    Use tabs when the content is genuinely parallel, such as cloud vs local setup, JavaScript vs Go examples, or conceptual vs raw source views.
  </Tab>
  <Tab value="Pattern">
    Keep labels short, avoid using tabs for long narrative sections, and prefer one active comparison at a time.
  </Tab>
</Tabs>
