# Semantic Routing

Semantic routing is an advanced **Execute**-stage mechanism.

Its job is to help Igris choose among eligible execution paths based on the kind of work being requested, instead of treating every request as identical. This is useful for advanced operators, but it is not the main reason to adopt Igris.

Use [Request -> Execute -> Verify](/docs/request-execute-verify) for the primary product model. Use this page when you want the deeper path-selection detail.

---

## What It Does

Semantic routing adds a classification step before final path selection.

In practice, that means Igris can:

- classify the request into a workload type
- narrow the eligible providers or paths for that class
- choose among those candidates with health and policy still applied

This is meant to improve path selection for advanced workloads, not to override governance, policy, or verification.

## Where It Fits

The simplified stack is:

1. policy decides what is allowed
2. health and trust narrow what is currently usable
3. semantic routing helps classify the work
4. final selection chooses the target path

That layering matters because semantic routing should stay subordinate to safety and policy controls.

## Decision Flow

```text
Request
  -> classification
  -> workload class
  -> eligible providers or paths
  -> final selection
  -> execution
```

## Fallback Behavior

Semantic routing should not be a hard dependency for execution.

If classification is unavailable, the system should still be able to continue with non-semantic path selection rather than turning classifier issues into execution outages.

That is the operator-friendly reason to treat this as an advanced mechanism rather than a foundational identity claim.

## What To Expect

Teams using semantic routing should expect:

- class-specific path selection behavior
- changing decisions as observations accumulate
- the need for explicit policy overrides when deterministic routing is required

Do not assume a semantic strategy stays fixed across time unless you pin the path explicitly.

## Proof Language

Semantic routing is best treated as an advanced, source-confirmed capability. Code and route surfaces exist, but this page should not promise specific quality, reliability, or cost outcomes without workload-specific evidence.
