# Swarm Coordination (Technical Preview)

Swarm-oriented coordination in Igris is an advanced surface.

It sits under the **Execute** stage and should not be treated as the default product path. If you are new to Igris, start with [Request -> Execute -> Verify](/docs/request-execute-verify) and [First Verified Run](/docs/first-verified-run).

See [Proof Status](/docs/proof-status) before planning around this page.

---

## Two Advanced Patterns

### Multi-Path Review

Some workflows send the same task through more than one model or provider path, then compare or synthesize outcomes. This can be useful for high-scrutiny tasks, but it increases cost and complexity and should be enabled deliberately.

### Environment Broadcast

Other workflows coordinate actions across more than one execution environment. This is useful when operators need a consistent rollout, command, or state change across registered environments.

---

## What To Expect

These patterns are best understood as:

- advanced operator workflows
- specialized coordination mechanisms
- areas that require stronger proof before they should be marketed as broadly production-ready

Do not assume autonomous fleet behavior, automatic failover, or guaranteed rollout semantics from the presence of these surfaces alone.

---

## Practical Guidance

Use swarm-style features only when you need them for a specific operational reason:

- coordinated rollout across registered environments
- deliberate multi-path review for higher-confidence tasks
- controlled experimentation on advanced execution behavior

If your main need is governed execution with visibility and receipts, the default execution model is simpler and better proven.
