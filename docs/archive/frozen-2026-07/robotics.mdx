# Robotics (Technical Preview)

Robotics is a **technical preview** execution surface.

Use this page as an orientation point for specialized teams exploring how the Igris execution model could extend toward physical systems. Do not treat it as a primary product claim or as proof of broad robotics readiness.

See [Proof Status](/docs/proof-status) before promoting robotics behavior beyond preview language.

---

## How Robotics Fits The Product Model

Robotics is still described using Request -> Execute -> Verify:

- **Request** defines the work the system is being asked to perform
- **Execute** happens in a robotics-adjacent runtime environment
- **Verify** depends on the records, events, and receipts produced by that run

That means robotics is a specialized execution surface under the same product model, not a different product identity.

## What This Page Is For

This page is useful if you are exploring:

- running governed execution closer to physical systems
- integrating runtime-side decisions with robotics environments
- thinking about how behavior trees, approvals, and signed records might apply to robotic tasks

## What To Say Carefully

Use conservative language:

- robotics execution is an advanced area
- proof status is limited
- do not assume fleet, OTA, or autonomous mission behavior is already broadly ready from this page

## Practical Reading

If you are a robotics team, the right way to use this page is:

1. understand the general Igris execution model first
2. treat robotics surfaces as technical preview
3. validate any physical-system workflow in your own environment before promoting it operationally
