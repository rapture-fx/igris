# Shadow Mode

Shadow mode is an advanced comparison workflow.

It can run an observed parallel path beside the primary execution path so operators can compare outcomes without immediately changing what the caller receives. That makes it useful for evaluation and tuning, but it should be treated as an advanced feature rather than a first-contact product claim.

---

## What It Does

At a high level:

```text
Request
  -> primary execution result returned
  -> shadow result captured separately for comparison
```

The important idea is that the shadow path is for observation, not for replacing the primary path automatically.

## Why Teams Use It

Shadow mode can help teams:

- compare candidate providers or models
- test a new configuration with lower risk
- observe how an alternate path behaves before changing the primary path

It is most useful when the team already has a stable baseline and wants to inspect alternatives carefully.

## How To Read The Results

A shadow comparison is only useful if the team knows what it is looking for:

- latency differences
- cost differences
- divergence in result shape or quality
- differences in policy-sensitive behavior

Treat the comparison output as decision support, not as a proof that the shadow path is ready for promotion.

## Proof Language

Shadow mode is best treated as an advanced or preview-oriented capability unless you have deployment-specific evidence for the exact workflow you are describing. It is appropriate to explain the comparison model, but not to overstate its production-readiness across every environment.

## Cost And Scope

Shadow execution may consume additional resources. Use it deliberately, with explicit scope and sampling decisions, rather than leaving it on broadly without a reason.
